# dsh-agy-provider 0.2.0 开发计划

状态：In progress（V2-M5 已完成，下一步 V2-M6）
规划日期：2026-08-18
基线版本：`dsh-agy-provider@0.1.0`

## 1. 版本目标

`0.2.0` 将已发布的文本 Provider MVP 提升为可在真实 DSH 环境中安装、发现、诊断和维护的版本，同时继续通过本机 AGY CLI 使用已登录账号的模型额度。

主链路保持不变：

```text
DSH
  → dsh-agy-provider
  → local agy CLI
  → AGY account quota
```

本版本不改变工具执行所有权：AGY 继续独占内部工具执行，Provider 不把 AGY 工具事件转换成 DSH tool call。

## 3. 成功标准

发布 `0.2.0` 前必须同时满足：

1. 在隔离目录安装公开 npm 包和固定版本 DSH CLI，DSH 能加载 bundle、发现 `agy` Provider 和模型。
2. Mock 路由完成无额度 smoke test；真实 AGY 路由完成一次人工授权的最小文本请求。
3. `0.1.0` 配置继续有效；新增配置必须有默认值、Schema 校验和迁移说明。
4. Windows 完成真实 AGY 验证；Linux/macOS 至少完成单元测试、构建和包安装验证，并明确未验证边界。
5. 诊断输出能区分 DSH、插件、Node.js、AGY、Agent、模型目录和配置问题，且不输出 Prompt、token 或用户路径。
6. AGY 未知事件继续前向兼容；认证、额度、模型、权限、超时和输出上限映射为稳定错误码。
7. CI、包预览和干净安装通过；npm 发布不再依赖长期保存在本机的 bypass-2FA token。

## 4. 本版本范围

### 必做

- 真实 DSH CLI 安装、bundle 激活和 Provider 发现闭环。
- 可机器读取的诊断结果及更清晰的错误分类。
- 多模型目录配置，避免选择器只显示一个固定模型。
- AGY 事件兼容夹具和内部工具进度的安全可观测性。
- Windows/Linux/macOS 的工程级 CI 矩阵；真实 AGY 仍以 Windows 为发布基线。
- 上下文成本复测和持久化 Session 的证据门槛。
- GitHub Actions 与 npm 发布链路加固。

### 明确不做

- 不移除 AGY，不直连 Gemini API。
- 不把 DSH tools 转发给 AGY，也不把 AGY 工具伪装成 DSH tool call。
- 不在 0.2.0 实现图像、多模态或完整采样参数映射。
- 不默认启用 `sessionMode: resume`，除非新基准证明它在目标会话长度下稳定节省额度。
- 不自动修改 AGY 登录、账号权限或额度配置。

## 5.1 当前执行检查点

- 在隔离临时目录安装 `@deepseek-ai/dsh@0.1.0-rc.7` 与公开的 `dsh-agy-provider@0.1.0`。
- 通过 `dsh plugin add` 激活 Provider bundle，并确认 profile 配置包含 `dsh-agy-provider`。
- 通过 `npm run smoke:dsh` 完成 Windows DSH CLI、bundle 配置和 Mock Provider runtime smoke test。
- smoke 输出明确标记 `quotaUsed: false`；随后获准执行的一次真实请求返回 `AGY_REAL_SMOKE_OK`，退出码为 0。

- 直接禁用整个 `tools` runtime 会导致 DSH 缺少 `agent-loop` 工厂，不能作为 overlay 方案。
- 真实请求结束后检查 `agy.exe` 进程数为 0；初始发现的本次请求残留进程已按父进程链确认并终止。
- `pnpm peers check` 报告部分 DSH host peer 未在插件 profile 中单独解析，但 DSH headless runtime 已成功加载并执行 Mock 请求；该项作为安装体验改进跟踪，不阻塞当前 V2-M1。
- V2-M2 已完成：`Config.models` 兼容旧 `model`，按精确 `id` 去重并保留未知请求模型；Provider 和 Mock runtime 返回文本能力、名称、描述和可选 `contextWindow`。
- V2-M2 已完成：`npm run diagnose -- --json` 返回 `schemaVersion: 1`、组件级稳定错误码和 `quotaUsed: false`；本机复验为 Node.js `24.18.0`、AGY `1.1.14`、Agent `deepseek-proxy`，无模型请求。
- V2-M2 安全边界：诊断只输出 AGY 可执行文件来源标签，不输出完整用户路径、Prompt、凭据或 Token。
- V2-M3 已完成：事件 fixture 覆盖已观测生命周期、工具/权限、错误和未知事件；日志增加固定类别计数与最终 status，不输出原始 payload。
- V2-M3 已完成：认证、额度、速率限制、未知模型、Agent 缺失和上下文超限使用稳定 Provider code；timeout、abort、parse、output limit、permission 等既有 code 完成回归验证。
- V2-M4 已完成：Process Adapter 使用 POSIX process group 和 Windows `taskkill /T` 清理进程树；父子 Node fixture 的 timeout/abort 回归通过。
- V2-M4 已完成：CI 扩展为 Windows/Ubuntu/macOS × Node.js 20/22/24，并升级 `actions/checkout`、`actions/setup-node` 到 `v7`；公共 CI 只做无额度验证。
- V2-M5 额度预算已固定：最多 12 次实际 AGY 请求、累计输入 60,000 tokens、输出 6,000 tokens；首组为 `full/resume` 各 2 轮，`resume` 未节省至少 20% 时自动止损。
- V2-M5 已完成：实际执行 4 次请求，累计 22,699 input / 857 output tokens；`full` 第二轮为 4,529 input，`resume` 第二轮为 9,224，节省率 `-103.67%`，因此关闭持久化 Session 闸门并保持 `full` 默认值。详见 `docs/quota-experiment-report.md`。

## 6. 详细实施计划

### V2-M0：基线校正与范围冻结

任务：

1. 将本地规划状态从“0.1.0 待发布”校正为“已发布”。
2. 固定 DSH CLI/LLM 契约、AGY 和 Node.js 基线。
3. 建立 0.2.0 测试夹具目录，区分无额度 fixture、Mock runtime 和人工真实请求。
4. 为新增配置和错误码建立兼容性清单。
5. 确认 GitHub 仓库是否继续 private；若继续 private，确保 npm 包内包含公开用户需要的完整文档。

验收：

- 计划、基线、非目标和决策闸门无矛盾。
- 所有真实模型调用都标记为人工触发，CI 不消耗 AGY 额度。
- 未在源码、fixture、日志或 npm tarball 中引入凭据。

### V2-M1：真实 DSH 安装与 bundle 激活

任务：

1. 在隔离临时目录安装 `@deepseek-ai/dsh@0.1.0-rc.7`。
2. 从 npm 安装 `dsh-agy-provider`，验证 `dsh.bundle.patch` 和 `cordis.patch.yml`。
3. 通过 DSH CLI 检查插件 inventory、Provider route 和模型目录。
4. 先用 `agy-mock` 完成无额度请求，再由人工确认执行一次真实 AGY 最小请求。
5. 将 smoke 流程固化为脚本；脚本不得读取或打印 npm token、AGY token、Prompt 历史或用户路径。

验收：

- 全新临时目录可从公开 npm registry 完成安装。
- DSH 能发现 `agy` Provider 和默认模型。
- Mock 流完整包含 `block-start → text-delta → block-end → usage → finish`。
- 真实最小请求可返回文本并正确结束，无残留 AGY 子进程。

阻塞规则：

- 若 DSH CLI 无法加载第三方 bundle，先记录真实 loader 错误和官方契约差异，不修改 AGY 适配层掩盖问题。

### V2-M2：诊断、能力与多模型目录

任务：

1. 为 `npm run diagnose` 增加 `--json`，保持默认人类可读输出。
2. 诊断项覆盖 Node.js、插件版本、DSH 目标版本、AGY 路径/版本、Agent、默认模型和 bundle 配置。
3. 新增 `models` 配置数组；`model` 仍是默认模型，保持 0.1.0 兼容。
4. `listModels()` 返回去重后的配置目录；`resolveModel()` 对未配置模型采用明确策略，不静默改写模型名。
5. 若 AGY 暴露稳定模型发现命令，再增加可选动态发现；否则只使用显式配置，不解析不稳定帮助文本。

验收：

- JSON 诊断具有稳定 Schema 和版本字段。
- 诊断失败返回非零退出码和稳定 code，不触发模型请求。
- 单模型旧配置和多模型新配置均通过官方 DSH runtime 测试。
- 任何诊断输出都不包含 Prompt、凭据或完整用户目录。

实现结果：上述验收已通过；配置、诊断安全、模型目录和官方 DSH runtime 共 47 个测试全部通过。下一阶段进入 V2-M3 的事件夹具、稳定错误分类和安全可观测性。

### V2-M3：事件兼容、错误分类与可观测性

任务：

1. 对已知 `init`、`step_update`、`checkpoint`、`agent_response`、`result`、工具和权限事件建立脱敏 fixture。
2. 将认证失败、额度限制、未知模型、Agent 缺失、权限请求、超时、取消、输出超限和非零退出映射为稳定错误码。
3. 在结构化日志中增加事件类别计数和最终 AGY 状态，不记录原始 Prompt/response/stderr。
4. 评估是否可将 AGY 的纯文本思考过程安全映射为 `reasoning-delta`；只有 Schema 稳定且不会泄露工具参数时才实现。
5. AGY 工具事件只作为内部进度和计数，不产生 DSH `tool-call-delta`。

验收：

- 每个错误码至少有一个 fixture 测试。
- 未知事件不导致崩溃，超长或恶意事件仍有界失败。
- 同一错误在 Windows/POSIX fixture 下产生相同 Provider code。
- 不改变 AGY 单一工具执行所有者规则。

实现结果：上述验收已通过，共 52 个测试全部通过。未发现可安全依赖的 AGY reasoning envelope，因此 `reasoning-delta` 暂不实现。下一阶段进入 V2-M4 跨平台进程测试与 CI 加固。

### V2-M4：跨平台进程行为与 CI 加固

任务：

1. 为 Windows、Linux、macOS 增加路径发现和命令名测试。
2. 验证 timeout/abort 后主进程与子进程树的清理行为；必要时引入平台专用的有界终止策略。
3. CI 扩展到 Windows、Ubuntu、macOS；Node.js 覆盖 20/22/24，其中完整矩阵与快速矩阵分层控制耗时。
4. 将 `actions/checkout`、`actions/setup-node` 升级到当前受支持 major，消除 Node 20 action runtime 弃用告警。
5. 每个平台执行 typecheck、unit test 和 `npm pack --dry-run`；真实 AGY 测试不进入公共 CI。

验收：

- 所有平台的无 AGY 测试通过。
- shell metacharacters 始终保持在单独 argv，不经过 Shell。
- abort/timeout 测试无悬挂进程，测试进程能在限定时间内退出。
- CI 不读取用户 npm/AGY 凭据。

实现结果：上述验收已通过，共 55 个测试全部通过。Linux/macOS 的结论限定为工程和进程行为验证，真实 AGY CLI 仍以 Windows 为发布基线。V2-M5 已完成，下一阶段进入 V2-M6 发布加固与 `0.2.0` 验收。

### V2-M5：上下文成本与 Session 持久化决策

任务：

1. 设计 2/10/30 轮可复现实验，对比 `full` 与 `resume` 的 input/cache/output tokens；在本轮预算内先执行 2 轮闸门样本。
2. 每次真实实验设定最大请求数和额度预算，必须人工触发；本轮上限为 12 次请求、60,000 input tokens、6,000 output tokens。
3. 记录 AGY conversation 恢复成功率、进程重启后的行为和上下文串线风险。
4. 只有当 `resume` 在目标会话长度下稳定节省至少 20% input tokens，才实现可选持久化 store。
5. 若实现持久化，只保存最小映射、版本和过期时间；DSH session ID 使用不可逆摘要，不保存 Prompt 或 response。

本轮采用早停策略：首组 `full/resume` 各 2 轮共 4 次请求；只有 `resume` 第二轮相对 `full` 节省至少 20% 才继续下一组，避免在已显示劣势的策略上继续消耗额度。可复现实验入口见 `docs/quota-experiment.md` 与 `npm run quota:experiment -- --live`。

本轮结果：实际 4 次请求，累计 `inputTokens=22,699`、`outputTokens=857`；`full` 第二轮为 `4,529`，`resume` 第二轮为 `9,224`，节省率为 `-103.67%`。门槛关闭，持久化 store 延期，默认策略保持 `full`。完整报告见 `docs/quota-experiment-report.md`。

验收：

- 形成可复测的 quota 报告和明确结论。
- 默认策略有数据支持；无证据时继续保持 `full`。
- 持久化功能若未通过收益/安全闸门，则明确延期，不为凑版本范围强行实现。

### V2-M6：发布加固与 0.2.0 发布

5. 创建 `v0.2.0` tag，发布 npm `latest`，再从 registry 安装发布产物复验。

验收：

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| DSH 仍是 RC，loader/API 变化 | 插件无法加载 | 固定 revision/tag，契约测试先行，适配层隔离 |
| AGY stream-json 事件漂移 | 解析或错误映射失效 | 脱敏 fixture、未知事件透传、最低版本诊断 |
| 多平台终止行为不同 | 残留子进程 | 平台测试、限定终止策略、超时回收 |
| resume 反而增加额度 | 用户成本上升 | 数据闸门，默认保持 full |
| public npm + private GitHub 文档断链 | 用户无法获取说明 | 发布前明确仓库可见性或把必要文档打入 npm 包 |
| 长期 bypass token | 发布凭据风险 | Trusted Publishing/OIDC、短期身份、最小权限 |
