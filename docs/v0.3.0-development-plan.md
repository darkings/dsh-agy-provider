# dsh-agy-provider 0.3.0 开发计划

状态：In progress（0.2.0 重新验收通过，V3-M0–V3-M5 已完成，V3-M6 发布准备中）
规划日期：2026-08-18
基线版本：`dsh-agy-provider@0.2.0`

## 1. 版本目标

`0.3.0` 将 Provider 从“静态配置可用”推进到“能够感知本机 AGY 能力并在 DSH 中安全使用”的版本，重点解决三个用户可见问题：

1. 不再要求用户手工维护完整模型列表，Provider 可通过 `agy models` 发现本机账号当前可用模型。
2. DSH 的 `reasoningEffort` 可精确映射到 AGY `--effort low|medium|high`。
3. 默认 DSH profile 携带 tools 时，用户可显式选择由 AGY 独占工具执行，而不必维护临时 text-only overlay。

主链路保持不变：

```text
DSH
  → dsh-agy-provider
  → local agy CLI
  → AGY account quota and models
```

`0.3.0` 不移除 AGY，不直连 Gemini API，也不把 AGY 内部工具重新包装为 DSH tool calls。

## 2. 规划决策

| 主题 | 0.3.0 决策 |
|------|------------|
| 模型发现 | 默认 `auto`；quota-free 调用 `agy models`，失败时使用最近成功缓存或静态配置 |
| 静态配置 | `model`/`models` 完整兼容 0.2.0；显式 metadata 和顺序优先 |
| 推理强度 | 只接受 `low`、`medium`、`high`，一对一传给 `--effort`；不设置隐式默认值 |
| DSH tools | 默认继续 `reject`；新增显式 `agy-owned` 策略，只忽略 DSH schemas，不改变工具所有者 |
| 权限 | 始终 fail-fast；不默认、不隐式传入 `--dangerously-skip-permissions` |
| Session | 默认继续 `full`；不恢复已被 0.2.0 成本实验否决的跨进程持久化 Session |
| 传输 | `one-shot` 继续为默认；持久 `stream-json` 只做有门槛实验 |
| DSH 契约 | 继续锁定 `@deepseek-ai/dsh-llm@0.1.0-rc.7`，除非上游出现并通过的新契约 |
| 发布 | 功能主线不依赖 npm 2FA；发布时优先 Trusted Publisher，失败则按既有安全边界处理 |

## 4. 成功标准

发布 `0.3.0` 前必须同时满足：

1. `agy models` 成功时，DSH 模型选择器可看到动态模型；失败、超时或输出异常时仍可使用 0.2.0 静态目录和默认模型。
2. 模型发现不发送 Prompt、不调用模型、不执行工具，并在诊断中保持 `quotaUsed: false`。
3. 同一时刻最多一个发现命令刷新缓存；缓存、超时和失败回退均有确定性测试。
4. DSH runtime 能校验 `low|medium|high`，Provider 将合法值作为独立 argv 传给 AGY；非法值在模型进程 I/O 前失败。
5. `toolPolicy: reject` 保持 0.2.0 行为；`agy-owned` 必须由用户显式启用，且权限请求仍返回 `PERMISSION_REQUIRED`。
6. 0.2.0 配置无需修改即可运行；新增配置均有安全默认值、Schema 边界和迁移说明。
7. `npm run verify`、官方 DSH runtime、隔离 DSH bundle smoke、跨平台 CI 和 registry 产物复验通过。
8. 任何真实 AGY 验证都受请求数和 token 预算控制；公共 CI 永不消耗 AGY 额度。

## 5. 本版本范围

### 必做

- 动态 AGY 模型发现、解析、合并、缓存、超时和静态 fallback。
- 动态目录的诊断可见性，包括来源、缓存状态、最后一次安全错误和 fallback 状态。
- DSH reasoning metadata，以及 `reasoningEffort → --effort` 参数映射。
- 显式 `toolPolicy: agy-owned`，解决默认 DSH tool-enabled profile 的接入摩擦。
- 配置、诊断、错误、日志、README、安装/迁移/兼容性文档和发布复验。

### 实验闸门

- 评估长驻 `agy --input-format stream-json --output-format stream-json` transport。
- 只有隔离、取消、崩溃恢复、资源回收和实机收益全部过线时，才以显式实验配置进入 `0.3.0`。
- 未过线时保留研究报告，不创建半成品运行配置，`one-shot` 继续作为唯一正式传输。

### 明确不做

- 不直连 Gemini/OpenAI-compatible API，不绕过 AGY 额度入口。
- 不实现完整 DSH ↔ AGY 双向工具桥接，不生成 DSH `tool-call-delta`。
- 不支持图像、多模态、`--json-schema` 结构化输出或 AGY sandbox 管理。
- 不映射 `temperature`、`maxTokens`、`stop`；AGY 1.1.14 CLI 没有对应参数。
- 不启用跨进程 Conversation 持久化，不把 `sessionMode: resume` 改成默认。
- 不自动登录 AGY、不修改账号权限、不读取或输出凭据。
- 不自动启用 `--dangerously-skip-permissions`。

## 7. 详细实施计划

### V3-M0：基线审计与范围冻结

任务：

1. 将 0.2.0 状态校正为完成，记录 npm/源码/CI/诊断基线。
2. 核对 AGY 1.1.14 的 `models`、`--effort` 和 stream-json 输入能力。
3. 核对 DSH 的异步 `listModels()`、`resolveModel()`、reasoning metadata 和目录刷新契约。
4. 固化本计划中的默认值、非目标、真实额度预算和升级闸门。

验收：

- 计划与当前代码、npm registry 和 DSH/AGY 契约一致。
- 0.3.0 没有依赖猜测性 API 的必做项。
- `npm run verify` 通过 55/55 tests；`npm run diagnose -- --json` 返回 `quotaUsed: false`。

### V3-M1：动态模型发现

任务：

1. 新增 `parseAgyModels()`，只接受合法非空 ID；显示名可选，重复 ID 保留第一条稳定结果。
2. 新增 quota-free discovery service，通过现有无 Shell process runner 执行 `agy models`。
3. 实现 single-flight、TTL、命令超时、最近成功缓存和静态 fallback；不写入磁盘。
4. 合并目录：显式 `models` 保持顺序并覆盖 metadata，动态模型补入其余条目，旧 `model` 始终存在。
5. 明确 DSH 目录刷新行为；若当前 runtime 不提供 adapter 内部变更通知入口，则仅在 `listModels()` 时刷新，并文档化“运行中变更需重新加载 profile”。
6. 诊断输出增加 discovery source、cache/fallback 状态和脱敏错误；对机器 Schema 做版本化处理。

建议配置：

```yaml
modelDiscovery: auto       # auto | off
modelDiscoveryTtlMs: 300000
modelDiscoveryTimeoutMs: 10000
```

验收：

- 正常、空输出、重复、CRLF、恶意行、超时、取消、非零退出和命令不存在均有测试。
- 并发调用只触发一个命令；失败不会清除最近成功缓存。
- `modelDiscovery: off` 完全恢复 0.2.0 静态行为。
- 发现命令日志不包含本机路径、环境值或原始 stderr。

实施结果（2026-08-18）：`src/agy/models.ts` 已实现严格解析、显式目录合并、进程内 TTL、single-flight、最近成功缓存和静态 fallback；`AgyAdapter.listModels()` 与诊断已接入动态目录。新增模型、配置、Provider、诊断和 DSH runtime smoke 测试后，本地测试为 60/60 通过；真实诊断发现 14 个模型，`quotaUsed=false`。

### V3-M2：Reasoning effort

任务：

1. 在 `resolveModel()` 中公开 `low`、`medium`、`high` 的 reasoning metadata。
2. 不设置 `defaultEffort`，保持 AGY/模型自身默认值。
3. 扩展 `AgyRequest` 和 `buildAgyArgs()`，将合法值映射为独立的 `--effort <value>` argv。
4. 从通用不支持选项检查中只移除 `reasoningEffort`；`temperature`、`maxTokens`、`stop` 继续 fail-fast。
5. 在官方 DSH runtime 中验证合法 effort，并验证非法 effort 在 spawn 前返回 `UNSUPPORTED_REASONING_EFFORT`。

验收：

- 三个 effort 的 metadata 顺序稳定，selector 名称可读。
- 未指定 effort 时 argv 中不存在 `--effort`。
- shell metacharacters 和非白名单字符串不能进入 argv。
- Mock/unit 测试不调用 AGY；实机只做有预算的最小对照。

实施结果（2026-08-18）：`AgyRequest` 增加白名单 reasoning effort，`buildAgyArgs()` 以独立 argv 传入 `--effort`；`AgyAdapter.resolveModel()` 公开三档 metadata，未设置 `defaultEffort`，非法值在 spawn 前返回 `UNSUPPORTED_REASONING_EFFORT`。官方 DSH runtime、Provider 和参数构造测试均通过，本地测试为 64/64。

### V3-M3：AGY-owned 工具策略

任务：

1. 新增 `toolPolicy: reject | agy-owned`，默认 `reject`。
2. `reject` 对非空 DSH tools 继续返回 `UNSUPPORTED_TOOLS`，保持 0.2.0 行为。
3. `agy-owned` 忽略 DSH tool schemas，只把文本上下文交给 AGY；日志只记录 schema 数量和策略，不记录参数。
4. AGY 内部工具继续由 AGY 独占，不映射为 DSH tool chunks。
5. 权限请求在两种策略下都立即终止并返回 `PERMISSION_REQUIRED`。
6. 提供可复制的 DSH 配置示例，并在默认 headless profile 上做 Mock 与最小实机验证。

验收：

- 未配置时行为与 0.2.0 完全一致。
- `agy-owned` 不会产生双重工具执行，也不会自动批准权限。
- 默认 DSH tool-enabled profile 可在显式 `agy-owned` 下完成文本响应。
- 文档明确说明 DSH tool schemas 在该策略下不会被模型按 DSH 协议调用。

实施结果（2026-08-18）：已新增 `toolPolicy` Schema、默认 bundle 配置、Adapter 双策略分支、诊断字段和白名单日志字段；默认 `reject`、显式 `agy-owned` 官方 DSH runtime、AGY 内部工具不生成 DSH tool chunks、两种策略权限 fail-fast、配置/安全/迁移文档测试均通过。`npm run verify` 通过 66/66 tests、typecheck 和 34-file pack dry-run；提交 `5893905` 已推送，GitHub Actions run `32145046428` 的 9 个跨平台 job 全部成功。当前 shell 无 `DSH_HOME`/`DSH_BIN`，未运行脚本级隔离 DSH smoke，未发起真实 AGY 模型请求；这两项保留为有环境/额度时的补充验证，不阻塞本阶段代码交付。

### V3-M4：持久 stream transport 实验

任务：

1. 先制作独立 prototype，不直接修改默认 `runProcess()` 生命周期。
2. 建立一个 DSH session 对应一个受控 AGY worker 的所有权模型；不同 session 输出必须严格隔离。
3. 实现有界 stdin 写入、NDJSON framing、请求关联、空闲 TTL、最大 worker 数、崩溃重启和关闭回收。
4. 验证 abort/timeout/output-limit 后 worker 状态，不允许把残余输出交给下一请求。
5. 使用 fixture 完成 100 轮串行、8 session 并发、故障注入和进程树回收。
6. 通过 fixture 后才执行实机 one-shot/persistent 对照；记录首 token 延迟、总耗时和 usage，不记录内容。

进入 0.3.0 的全部门槛：

- 0 次跨 session/跨 request 输出串线。
- abort、timeout、崩溃和插件 dispose 后无残留 AGY 进程。
- 实机 3 对 3 最小样本中，persistent 的首 token 延迟中位数改善至少 15%，且 input tokens 不增加超过 5%。
- 配置必须显式标记 experimental，默认仍为 `one-shot`。

任一门槛失败：停止实机实验，记录结论，0.3.0 不发布持久 transport。

实施结果（2026-08-18）：新增隔离的 `ExperimentalAgyTransport`、受控 NDJSON worker fixture 和 72 项测试；已通过 100 轮串行、8 Session 并发、最大 worker、idle TTL、crash recovery、abort/timeout/output-limit、request/session correlation、进程树 timeout 和 `dispose()` 回收闸门。实现未接入 `AgyAdapter`、`Config`、`src/index.ts` 或默认 `sessionMode`，one-shot 仍是唯一正式传输。由于本阶段只完成无额度 fixture gate，未发起真实 AGY 模型请求，真实 AGY `--input-format stream-json` 协议与 3+3 收益对照保留为后续显式实验，不作为本次完成条件。详见 `docs/experimental-stream-transport.md`。

3. 在 Windows/Ubuntu/macOS × Node.js 20/22/24 跑 typecheck、tests、pack dry-run。
4. 在固定 DSH `0.1.0-rc.7` 上验证动态目录、effort capability 和 tool policy。
5. 检查上游 DSH/AGY 是否变化；只有契约测试通过才升级锁定版本。

验收：

| `model` | 默认模型/fallback | 无变化 |
| `models` | 静态目录 | 保留，metadata/顺序优先于动态发现 |
| `modelDiscovery` | 不存在 | 新增，默认 `auto`，可设 `off` |
| `modelDiscoveryTtlMs` | 不存在 | 新增，默认 `300000` |
| `modelDiscoveryTimeoutMs` | 不存在 | 新增，默认 `10000` |
| `toolPolicy` | 固定拒绝 | 新增，默认 `reject`，可显式 `agy-owned` |
| `sessionMode` | `full`/`resume` | 保留，默认仍为 `full` |
| `reasoningEffort` | 拒绝 | 支持请求级 `low/medium/high` |
| `temperature/maxTokens/stop` | 拒绝 | 继续拒绝 |
| `transport` | one-shot | 默认不变；实验通过才增加显式 experimental 值 |

## 9. 测试与额度预算

| 层级 | 是否消耗额度 | 范围 |
|------|--------------|------|
| Parser/config/unit fixtures | 否 | models 解析、合并、缓存、effort argv、tool policy |
| Official DSH runtime | 否 | 目录、reasoning metadata、非法 effort、stream contract |
| DSH CLI + Mock | 否 | bundle、默认 profile、配置迁移和诊断 |
| Real AGY smoke | 是 | effort、AGY-owned 和最终最小验收 |
| Persistent transport experiment | 是 | 仅在 fixture 全过后执行 3+3 对照 |

本版本真实额度硬上限：

- 最多 10 次实际 AGY 模型请求。
- 累计最多 50,000 input tokens。
- 累计最多 5,000 output tokens。
- 任一上限达到即停止，不用剩余额度补样本。
- 动态模型发现、诊断、Mock、CI 和 pack 验证不计入请求数，因为不得调用模型。

建议分配：effort 2 次、AGY-owned 1 次、persistent 6 次、发布后最终 smoke 1 次。若 persistent fixture 未通过，其 6 次预算不转用于扩大其他实验。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| `agy models` 输出格式变化 | 目录为空或错误 | 严格解析、静态 fallback、最近成功缓存、脱敏 warning |
| 动态目录运行中变化无法通知 UI | selector 不及时刷新 | V3-M1 核对事件入口；无入口时要求 reload，不做后台轮询 |
| AGY effort 对部分模型不适用 | 实机请求失败 | DSH 先校验白名单，保留 AGY 稳定错误映射并文档化模型差异 |
| `agy-owned` 与 DSH system prompt 产生工具语义混淆 | 回答质量或工具行为异常 | 显式 opt-in、默认 reject、最小实机验证、唯一执行所有者 |
| 持久 worker 串线或残留 | 隐私与资源风险 | 独立实验、强隔离门槛、失败即不发布 |
| DSH RC 契约变化 | 插件加载失败 | 固定 rc.7、契约测试先行、升级独立处理 |
| private GitHub repo 无 provenance | 发布可验证性较弱 | 继续明确限制；2FA 可用后优先 Trusted Publisher |
| 真实测试消耗 AGY 额度 | 用户成本 | 10 次/50k/5k 硬上限和早停，不在 CI 执行 |

## 11. 实施顺序

1. V3-M1 先落地动态模型发现，因为它完全 quota-free，且为后续模型能力展示提供目录基础。
2. V3-M2 在同一模型 metadata 层加入 reasoning effort，并完成官方 DSH runtime 验证。
3. V3-M3 增加显式 AGY-owned 策略，解决真实 DSH 默认 profile 接入问题。
4. 核心功能稳定后执行 V3-M4；持久 transport 不阻塞前三项交付。
5. V3-M5 完成全矩阵、安全和兼容性复验。
6. 最后进入 V3-M6 文档、版本和发布；实现期间不提前占用 `0.3.0` registry 版本。

## 12. Definition of Done

`0.3.0` 只有在以下条件全部满足时才视为完成：

- 三条必做主线均有代码、测试、文档和 DSH runtime 证据。
- 0.2.0 配置和默认安全行为没有破坏性变化。
- 所有动态能力在失败时可回退，不阻断基础文本请求。
- 公共自动化不使用 AGY/npm 凭据，也不消耗模型额度。
- 实机测试未超过预算，结束后没有残留 AGY 进程。
- npm registry 产物、README、CHANGELOG 和迁移文档相互一致。
