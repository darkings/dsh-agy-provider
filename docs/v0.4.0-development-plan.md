## 2. 0.4.0 版本目标

0.4.0 聚焦两个可验证的产品能力：

1. 将 V3-M4 的隔离 persistent transport prototype 推进到“真实 AGY 协议已确认、收益有数据、失败可回退”的显式实验能力。
2. 建立自包含的本地 tarball → 隔离 DSH profile → bundle/Mock runtime smoke，使安装复验不依赖预先配置的 `DSH_HOME`/`DSH_BIN`。

主链路继续保持：

```text
DSH
  → dsh-agy-provider
  → local AGY CLI
  → AGY account quota and models
```

0.4.0 不绕过 AGY，不直接调用 Gemini/OpenAI API，也不改变 AGY 作为额度与认证入口的定位。

## 4. 成功标准

0.4.0 代码交付前必须满足：

1. 真实 AGY `--input-format stream-json --output-format stream-json` 输入/输出协议有最小、脱敏、可复现 fixture，不依赖猜测字段。
2. persistent transport 保持严格的 `sessionId`/`requestId` 双重关联；跨 Session/跨请求串线为 0。
3. abort、timeout、output-limit、协议错误、worker crash 和 dispose 后残余 AGY 进程为 0。
4. one-shot 与 persistent 完成 3 对 3 最小真实样本；persistent 首 token 延迟中位数至少改善 15%，input tokens 增幅不超过 5%。
5. 只有全部真实协议、隔离和收益门槛通过，才增加显式 `transport: persistent-experimental`；默认继续为 `one-shot`。
6. 若任一 persistent 门槛失败，0.4.0 仍可交付自包含 DSH smoke、诊断和兼容性改进，但不暴露 persistent 用户配置。
7. 本地 tarball 可以在临时目录安装到固定 DSH 版本，完成 bundle inventory、配置 dump 和 Mock 文本响应，结果标记 `quotaUsed=false`。
8. 0.2.0 配置无需修改即可运行；`sessionMode: full`、`toolPolicy: reject` 和 one-shot 默认值不变。
9. Windows/Ubuntu/macOS × Node.js 20/22/24 的 typecheck、tests、pack 和 benchmark 全部通过。
10. tarball、fixture、日志和诊断不包含 Prompt、完整用户路径、stderr、Token、凭据或本机安装目录。

## 5. 范围

### 必做

- 真实 AGY stream-json 协议采样、脱敏 fixture 和兼容性解析。
- persistent transport 的显式实验接入闸门、生命周期、回退和诊断。
- one-shot/persistent 受控真实对照与机器可读报告。
- 自包含本地 tarball/隔离 DSH Mock smoke。
- 安全日志、稳定错误码、跨平台进程树和安装文档更新。

### 条件性进入

- `transport: persistent-experimental`：只在协议、隔离、性能和 token 门槛全部通过后进入 public Config。
- 首 token 指标：只有 AGY stream-json 事件能稳定识别第一个文本 delta 时才记录；否则实验结论为协议不足，不伪造指标。
- 真实模型能力差异：只记录已验证模型，不把单模型结果扩展为所有模型承诺。

### 明确不做

- 不实现 DSH ↔ AGY 双向 tool-call bridge。
- 不自动批准权限，不传入 `--dangerously-skip-permissions`。
- 不把图片、多模态、`temperature`、`stop` 或 `maxTokens` 纳入本版本。
- 不在没有稳定 AGY envelope 时映射 `reasoning-delta`。
- 不默认启用 persistent transport，不改变 `sessionMode: full`。
- 不在公共 CI 中安装登录态 AGY、调用模型或使用 npm/AGY 凭据。
- 不在 2FA/Trusted Publisher 不可用时绕过发布安全闸门。

## 6. 真实 AGY 额度预算

用户已允许 0.4.0 进行真实 AGY 请求。硬上限为：

- 最多 8 次模型请求。
- 累计最多 40,000 input tokens。
- 累计最多 4,000 output tokens。
- 任一上限达到即停止，不把剩余额度转移到扩样。

建议分配：

| 用途 | 请求上限 | 说明 |
|------|----------|------|
| 协议握手/多轮 stream-json 确认 | 2 | 最小文本、无工具、固定短输出；可以复用为 persistent 预热样本 |
| one-shot 基线 | 3 | 相同模型、Agent、Prompt 和 effort |
| persistent 对照 | 3 | 与 one-shot 一一对应，不增加上下文内容 |

每次实验必须记录 request 序号、transport、模型、首 delta 延迟、总耗时、usage、退出/终止状态和残余进程数；不得记录 Prompt、模型正文或凭据。若第一次协议请求已证明 AGY 不支持预期会话 framing，立即停止后续 persistent 请求。

### V4-M1：真实 stream-json 协议采样

任务：

1. 新增显式人工实验脚本，要求预算参数和确认开关，默认不执行真实请求。
2. 以 `agy --print --input-format stream-json --output-format stream-json` 启动真实 AGY worker，确认 stdin 每行消息结构、turn 边界、conversation/session 标识和退出语义。
3. 采集最多 2 次最小文本请求；生成删除正文、路径、stderr 和标识符后的 fixture。

### V4-M2：persistent transport 显式实验接入

前置条件：V4-M1 证明真实协议可以稳定驱动多轮请求并关联输出。

任务：

1. 将真实协议 codec 与 worker pool 状态机分离，保留输入/输出/单行上限。
2. 接入 `AgyAdapter` 的内部 transport seam；默认 one-shot 路径零行为变化。
3. 只有门槛通过才添加 `transport: one-shot | persistent-experimental` Schema；实验值必须显式设置。
4. 定义 worker/session 所有权、max workers、idle TTL、启动超时、请求超时和 dispose 合同。
5. persistent 失败必须返回稳定错误；不得把未知执行状态静默重试为 one-shot，避免同一请求重复执行。
6. 增加真实协议 fixture 的 100 轮串行、8 Session 并发、错误关联、取消、崩溃和进程树测试。

验收：默认 one-shot 测试全部不变；persistent fixture 无串线、无残余进程；Config/诊断明确标记 experimental。

## 9. 关键技术决策

| 决策 | 理由 |
|------|------|
| 默认继续 one-shot | 当前唯一经过真实链路和跨平台进程测试的正式 transport |
| persistent 必须显式 experimental | 长驻 worker 会扩大隐私、串线、回收和协议兼容风险 |
| 协议 codec 与 worker pool 分离 | AGY envelope 变化不应破坏并发/生命周期状态机 |
| 不对未知执行状态自动重试 | 可能造成工具或副作用请求重复执行 |
| 真实实验采用 3+3 最小样本 | 在有限额度内提供可比较中位数，同时避免把噪声当结论 |
| DSH smoke 自包含 | 发布验收不能依赖开发机已有 profile 或环境变量 |
| 0.3 基线固定为 commit | 0.3 未发布时继续开发 0.4，必须保留可单独发布的干净边界 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| AGY stream-json envelope 未公开或变化 | persistent 无法稳定接入 | 真实采样、严格 codec、fixture 回归；失败即停止 |
| persistent 请求无法可靠关联 | 串线或隐私问题 | request/session 双校验，任何 mismatch 立即 reset worker |
| worker 在取消后继续运行 | 额度浪费或副作用 | 终止进程树、等待 close、残余进程计数为硬门槛 |
| 性能改善低于 15% | 复杂度收益不足 | 不暴露 transport 配置，保留 one-shot |
| token 成本增加 | 额度消耗上升 | input tokens +5% 硬上限，超限即否决 |
| 临时 DSH 安装受网络/包管理器影响 | smoke 不稳定 | 固定版本、缓存/超时、区分下载失败与运行失败 |
| 0.3/0.4 版本混淆 | 错发包或 changelog 不一致 | 固定 0.3 commit，版本 bump 前单独确认发布顺序 |
| npm 2FA 长期不可用 | 无法正式发布 | 开发与 release candidate 继续；不保存长期 token、不绕过安全闸门 |

## 13. 实施结果（2026-08-19）

### V4-M1：真实协议与 fixture

- 新增 `scripts/agy-protocol-experiment.mjs`，必须同时设置 `AGY_QUOTA_EXPERIMENT=ALLOW` 和 `--confirm-quota`，并将真实请求限制为最多 2 次；未满足闸门时不会启动 AGY。
- 本轮执行 2 次真实尝试：第一次因缺少空 print prompt 得到非 JSON 输出并正常退出；第二次使用 `-p ""` 成功得到 5 条事件，顺序为 `init → step_update(user_input) → step_update(agent_response) → step_update(checkpoint) → result`，`parseErrors=0`、进程退出码为 0、残余进程为 0。
- 有效样本 usage 为 `inputTokens=4414`、`outputTokens=301`；脚本只输出计数、字段形状、长度和数值 usage，不保存 Prompt、正文、路径、stderr 或标识符。
- 新增 `tests/fixtures/agy-stream-json-real.mjs` 和回放测试；fixture 中 conversation/path/tool/text/token 全部为占位值，未把 fixture-only 字段接入正式 Adapter。

### V4-M2/V4-M3：persistent go/no-go

- 真实采样确认了 AGY 输出 envelope 和首个文本 delta 字段，但本轮没有证明同一进程在第一条 terminal `result` 后能稳定接收第二个 stdin turn；因此 V4-M2 前置条件不满足。
- 未接入 `AgyAdapter`、`Config` 或 `src/index.ts`，未增加 `transport` 配置，不执行 3+3 真实性能对照，不宣称首 token 或 token 成本收益；本轮以 negative result 关闭 persistent 主线，默认 one-shot 保持不变。

### V4-M4：自包含 DSH smoke

- 新增 `scripts/dsh-smoke-self-contained.mjs` 与 `npm run smoke:dsh:self-contained`：临时安装 `@deepseek-ai/dsh@0.1.0-rc.7`、打包/安装当前 Provider、显式追加 `dsh-agy-provider` bundle，完成 `--dump-config`、bundle inventory 和 `agy-mock` 文本响应后清理。
- Windows 本机结果：`dshVersion=0.1.0-rc.7`、Provider `0.2.0`、model `agy-mock-model`、`toolPolicy=reject`、`quotaUsed=false`、`cleanup=completed`。
- CI 已加入 Ubuntu/macOS Node 24 的自包含 smoke job；该 job 不安装登录态 AGY、不读取凭据、不调用模型。

### 当前收尾边界

- 当前本地测试为 80/80，默认 one-shot、`sessionMode: full`、`toolPolicy: reject` 和 package version `0.2.0` 未改变。
- 真实 AGY 额度实验停止在 V4-M1 的 2 次尝试；不再追加请求，不执行 npm publish、version bump 或 release tag。下一步只做 typecheck/test/pack/CI/文档一致性收尾。
