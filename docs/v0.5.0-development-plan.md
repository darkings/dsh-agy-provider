# dsh-agy-provider 0.5.0 开发计划

状态：Planned（planning only；未修改运行时、未消耗 AGY 额度、未发布）
规划日期：2026-08-19
源码基线：提交 `863c91f`
registry 基线：`dsh-agy-provider@0.4.0`，`latest=0.4.0`
运行时基线：`@deepseek-ai/dsh@0.1.0-rc.7`、AGY `1.1.14`、Node.js `>=20`

## 1. 0.4.0 发布后审计

0.4.0 已完成文本 Provider、动态模型发现、reasoning effort、显式 AGY-owned 策略、自包含 DSH Mock smoke 和公开 npm 发布，但真实 DSH Web 首次使用暴露了产品化缺口：

| 维度 | 当前结论 | 0.5.0 缺口 |
|------|----------|------------|
| npm 包 | `0.4.0` 已公开发布 | npm README 的安装路径曾把普通 `npm install` 与 DSH profile 安装混为一谈 |
| DSH profile 安装 | `dsh plugin --profile web add` 可正确写入依赖和 bundles | 自包含 smoke 没有使用这条真实用户路径，而是手工修改 profile manifest |
| bundle 激活 | package metadata 与 patch 可被 DSH 识别 | bundle 默认 `enabled=false`，安装后仍需手工编辑 profile patch |
| 工具所有权 | `toolPolicy: agy-owned` 已实现并有 runtime 测试 | bundle 默认 `reject`，与 DSH Web 默认携带 tool schemas 冲突，首次请求返回 `UNSUPPORTED_TOOLS` |
| 诊断 | 源码仓库内 `npm run diagnose` 可用且 `quotaUsed=false` | npm 安装用户没有 package `bin`，无法直接运行面向 profile 的 doctor |
| Web smoke | 本机真实 profile 已验证可加载并启用 | CI 只验证 headless + 手工 bundle 追加，没有覆盖 `web` profile 的原生安装闭环 |
| CI 稳定性 | 主要矩阵长期通过 | Windows Node 24 的 persistent fixture 曾出现一次 child PID 启动竞态，重跑才通过 |

结论：0.5.0 的主线不是扩充模型协议，而是把 0.4.0 从“能够运行的 Provider”推进为“能够按 DSH 原生方式安装、发现、诊断和安全启用的 Web 插件”。

## 2. 版本目标

0.5.0 聚焦四个用户可见结果：

1. 用户执行一条 DSH profile 安装命令后，插件进入目标 profile，并以适合 AGY 自治 Agent 的 bundle 默认值启用。
2. DSH Web 默认附带 tool schemas 时不再触发 `UNSUPPORTED_TOOLS`；AGY 继续是唯一工具执行者，不建立双向 tool bridge。
3. npm 安装用户可以直接运行 quota-free doctor，判断 package、profile、bundle、AGY、Agent 和模型目录是否就绪。
4. CI 使用真实 `dsh plugin --profile <name> add` 路径验证 Web/headless profile，不再靠手工修改 manifest 掩盖安装缺口。

目标链路保持不变：

```text
DSH Web/headless profile
  → dsh-agy-provider bundle
  → local AGY CLI
  → AGY account quota and models
```

## 3. 关键产品决策

### 3.1 分离程序化默认值与 bundle 默认值

- `cordis.patch.yml` 对 DSH profile 安装显式写入 `enabled=true`、`toolPolicy=agy-owned`；DSH 的 `--dump-config` 按 bundle patch layer 组合配置，不依赖插件 schema default。
- 程序化库调用和公开入口 `Config`/`ConfigSchema` 继续保持 `enabled=false`、`toolPolicy=reject`；`BundleConfig` 仅作为显式 ready schema 导出，保护直接调用 API、测试和嵌入式使用者的兼容性。
- 用户仍可在 profile 的 `cordis.patch.yml` 中覆盖为 `enabled=false` 或 `toolPolicy=reject`。
- `agy-owned` 只忽略 DSH schemas，不把 schema、参数或 AGY 内部工具事件转换为 DSH tool calls。

### 3.2 DSH profile 命令是唯一推荐安装入口

推荐安装命令固定为：

```powershell
npx @deepseek-ai/dsh plugin --profile web add dsh-agy-provider@0.5.0
```

普通 `npm install dsh-agy-provider` 只用于 Node.js 代码直接导入，不宣称会修改 DSH profile。包不增加 postinstall，不在安装期间猜测或改写用户的其他 profile。

### 3.3 doctor 默认只读、零额度

- 新增 package `bin`，目标命令为 `npx dsh-agy-provider doctor --profile web`。
- doctor 只读取 profile manifest/组合配置，并执行 AGY `--version`、`agents`、`models` 等 quota-free 命令。
- doctor 不发送 Prompt、不启动模型请求、不执行工具、不输出凭据、完整路径、stderr 原文或用户配置正文。
- doctor 发现问题时输出精确修复命令或 patch 片段，但默认不自动写入 profile。

### 3.4 persistent transport 继续关闭

0.4.0 已因真实多轮 stdin 留存未证明而关闭 persistent 主线。0.5.0 不重新开放该配置，也不以 onboarding 版本为由改变 one-shot 和 `sessionMode: full` 默认值。

## 4. 成功标准

0.5.0 源码交付前必须满足：

1. 在全新临时 `DSH_HOME` 中运行 `dsh plugin --profile web add <local-tarball>` 后，profile dependency 与 `dsh.profile.bundles` 都包含 `dsh-agy-provider`。
2. 不手工修改 profile manifest 时，`--dump-config` 显示 bundle `enabled=true`、`toolPolicy=agy-owned`、`provider=agy`。
3. `src/provider/config.ts` 和公开入口的 `Config({})`/`ConfigSchema({})` 程序化默认值仍为 `enabled=false`、`toolPolicy=reject`；`BundleConfig({})` 明确提供 ready bundle schema，不把两种入口混用。
4. DSH runtime 传入非空 tool schemas 时，bundle 默认路径能返回文本流，不产生 DSH tool chunks，也不把 schema 内容传给 AGY。
5. `npx dsh-agy-provider doctor --profile web --json` 返回稳定机器格式、`quotaUsed=false`，并能区分 package 未安装、bundle 未声明、bundle 未启用、工具策略不匹配、AGY/Agent/模型目录异常。
6. `UNSUPPORTED_TOOLS`、`PERMISSION_REQUIRED` 和 profile 安装错误都包含可执行的修复提示，同时保持现有稳定 error code。
7. 自包含 smoke 覆盖 Web 与 headless profile，使用 DSH 原生 plugin add，不再手工写 `dsh.profile.bundles`。
8. Windows Node 24 的 persistent process-tree fixture 通过确定性启动握手消除偶发 child PID 竞态；发布前连续重复验证不得依赖手工 rerun。
9. Windows/Ubuntu/macOS × Node.js 20/22/24 的 typecheck、tests、pack、benchmark 全部通过；Ubuntu/macOS Node 24 profile smoke 通过。
10. 公共 CI 不读取用户 DSH/AGY 配置、不调用真实模型、不使用 AGY/npm 凭据，所有 profile smoke 均为 `quotaUsed=false`。

## 5. 范围

### 必做

- DSH bundle 安装后的 ready/AGY-owned 默认值与迁移兼容。
- package `bin` 与 profile-aware、quota-free doctor。
- `UNSUPPORTED_TOOLS` 等错误的可操作修复提示。
- DSH 原生 plugin add 的 Web/headless 自包含 smoke。
- Windows Node 24 fixture 启动竞态修复。
- README、安装、0.5.0 迁移、兼容性、CHANGELOG、发布清单同步。

### 条件性进入

- 一次真实 DSH Web → AGY 文本请求：只有无额度安装/诊断/Mock 闸门全部通过且用户再次确认额度后执行。
- Trusted Publisher tag 发布：只有 npm package settings 已连接 `darkings/dsh-agy-provider` 与 `publish.yml` 后执行；否则不创建会触发失败 workflow 的 tag。
- doctor 的自动修复模式：只有能保证 YAML 合并不覆盖用户现有 patch 时才进入；否则 0.5.0 只输出修复建议。

### 明确不做

- 不实现 DSH ↔ AGY 双向 tool-call bridge。
- 不自动批准权限，不传入 `--dangerously-skip-permissions`。
- 不重新开放 persistent transport，不新增后台常驻 AGY worker。
- 不改变 `sessionMode: full` 和 one-shot 正式路径。
- 不实现图片、多模态、sampling、`temperature`、`stop`、`maxTokens` 或 reasoning-delta。
- 不通过 postinstall 修改任意 DSH profile，不猜测用户希望启用哪个 profile。
- 不在公共 CI 中调用 AGY 模型或保存真实 Prompt/Response。

## 6. 真实 AGY 额度预算

本轮规划阶段真实请求为 0。0.5.0 的绝大多数验收必须通过 fake runner、Mock Provider 和 quota-free doctor 完成。

若实施末期用户明确授权真实 Web 复验，硬上限为：

- 最多 2 次模型请求（1 次正式验证，最多 1 次因环境故障重试）。
- 累计最多 12,000 input tokens。
- 累计最多 1,000 output tokens。
- 固定短文本输出，不调用有副作用的工具。
- 任一上限达到即停止；公共 CI 始终为 0 请求。

真实报告只记录请求序号、DSH profile、provider/model、tool policy、usage、耗时、退出状态和残余进程数，不保存 Prompt、回复正文、路径、conversation ID 或凭据。

## 8. 详细实施计划

### V5-M0：基线与范围冻结

任务：

1. 复核 0.4.0 npm、GitHub CI、DSH、AGY、Node.js 和本机 profile 基线。
2. 复现普通 npm 安装不进入 DSH profile、bundle 默认禁用和 `UNSUPPORTED_TOOLS` 首次使用问题。
3. 固定 0.5.0 主线为 profile onboarding、doctor、原生 smoke 和 CI 稳定性。
4. 固定真实额度上限与不记录字段。

验收：本计划、`task_plan.md`、`findings.md`、`progress.md` 一致；源码/package version/registry 不变；真实请求为 0。

### V5-M1：profile 安装契约与 bundle 默认值

任务：

1. 将 `cordis.patch.yml` 的 bundle 默认值改为 `enabled=true`、`toolPolicy=agy-owned`，保留 provider/model/agent/sessionMode 显式值。
2. 保持 `src/provider/config.ts` 与公开入口 `Config`/`ConfigSchema` 默认 `enabled=false`、`toolPolicy=reject`，导出显式 `BundleConfig` 供需要 ready defaults 的调用方使用；增加回归测试区分 library schema 与 bundle schema。
3. 增加 bundle patch 结构测试，防止发布时默认值被文档或 Schema 改动意外覆盖。
4. 固定推荐安装、升级、删除命令均通过 `dsh plugin --profile <profile>`；普通 npm 安装只作为库导入说明。
5. 验证 AGY 不在 PATH、Agent 缺失或模型发现失败时，DSH profile 仍能启动并由诊断提供问题，不在启动阶段执行模型请求。

验收：显式 DSH plugin add 后无需手工编辑即可在 Web profile 注册 `agy` adapter；直接 API 默认值无破坏性变化。

### V5-M2：已发布 doctor CLI

任务：

1. 新增 package `bin` 和 CLI 入口，支持 `doctor`、`--profile`、`--dsh-home`、`--dsh-bin`、`--json`、`--help`。
2. 复用 `diagnoseProvider()`/`diagnoseAgy()`，增加 profile 层检查：profile 存在、package dependency、bundle membership、组合配置中的 enabled/toolPolicy/provider/model。
3. DSH CLI 解析按“显式参数 → 当前依赖可解析 entry → PATH”执行，所有 spawn 保持 `shell=false`、有超时和输出上限。
4. 机器输出保留稳定 schema、`quotaUsed=false` 和稳定 code；人类输出给出精确安装/启用/策略修复命令。
5. doctor 不写 profile；如实现 `--fix`，必须先生成 dry-run diff、只修改目标 plugin id，并保留原 YAML/注释，否则延期。
6. 将 CLI 产物、类型和 shebang 纳入 tarball/Windows npm shim 测试。

验收：从打包 tarball 安装后可运行 doctor；Windows/Unix 路径都经过脱敏；AGY 请求计数为 0。

### V5-M3：可操作错误与工具所有权

任务：

1. 保持 `UNSUPPORTED_TOOLS` code 不变，将 message 更新为包含 `toolPolicy: agy-owned` 修复提示。
2. 为 `PERMISSION_REQUIRED` 增加“不自动授权、需调整 AGY Agent 权限/工具设计”的明确提示，不引入自动批准。
3. 在 `agy-owned` 下继续验证：DSH schema 数量只进入安全计数，schema 内容不进 Prompt、argv、日志或 stderr。
4. 增加 bundle 默认路径的官方 DSH runtime 测试，确认非空 tools 得到文本流且 0 个 DSH tool-call chunk。
5. 更新工具能力矩阵，明确 `reject` 是程序化/严格模式，`agy-owned` 是 DSH Web bundle 默认模式。

验收：真实 Web 默认 schema 不再导致拒绝；安全边界和稳定错误码保持。

### V5-M4：原生 profile 安装 smoke

任务：

1. 重构 `scripts/dsh-smoke-self-contained.mjs`，使用固定 DSH CLI 的 `plugin --profile <name> add <tarball>` 安装 Provider。
2. 删除 smoke 中手工写 `package.json.dsh.profile.bundles` 的捷径；将 dependency、bundle membership 和 lockfile 作为独立断言。
3. 对 `web` profile 验证 bundle inventory、`--dump-config`、ready/agy-owned 默认值和 plugin inventory。
4. 对 `headless` profile 继续使用额外 Mock patch 验证模型目录、tool schema 入口和文本响应；结果保持 `quotaUsed=false`。
5. 输出机器可读结果：DSH/Provider 版本、profile、安装方式、enabled/toolPolicy、bundle inventory、quotaUsed、cleanup。
6. finally 清理临时 profile、包缓存引用和子进程；输出不含临时绝对路径。

验收：Windows 本机通过；Ubuntu/macOS Node 24 CI 通过；整个流程不需要现有 `DSH_HOME`/`DSH_BIN` 或 AGY 登录态。

### V5-M5：CI、flake 与安全加固

任务：

1. 为 persistent fixture 的子进程启动增加确定性 ready/child PID 握手，移除依赖固定等待时间的断言。
2. 在 Windows Node 24 对目标 process-tree 测试执行受控重复，确认不是依赖 rerun 才通过。
3. 保持 Windows/Ubuntu/macOS × Node.js 20/22/24 verify/benchmark；Web/headless smoke 保持 Ubuntu/macOS Node 24。
4. 检查 CLI、profile 摘要、修复提示和日志不包含用户目录、Prompt、schema 参数、stderr 原文或凭据。
5. `npm pack --dry-run` 必须包含 CLI、bundle patch、types 和 README，不包含规划文件、测试 fixture、日志或本机 profile。

验收：所有矩阵一次通过；无 flaky rerun 依赖；公共 CI `quotaUsed=false`。

### V5-M6：文档、迁移与发布

任务：

1. 新增 0.5.0 迁移说明，突出 bundle 默认值变化、profile 安装命令、doctor 和严格 `reject` 选项。
2. 更新 README、安装、工具能力矩阵、兼容性、CHANGELOG 和发布清单。
3. 运行 typecheck、tests、benchmark、pack dry-run、doctor、Web/headless self-contained smoke 和 registry 版本占用检查。
4. 可选真实 Web 请求只有在用户再次授权后执行，并遵守 2/12k/1k 硬上限。
5. 将 package version 更新为 `0.5.0`；优先用已配置的 Trusted Publisher tag workflow 发布，未配置时不盲目推 tag。
6. 发布后通过 `dsh plugin --profile web add dsh-agy-provider@0.5.0` 从 registry 全新安装，复验 doctor、bundle defaults 和 Mock/可选真实链路。

验收：npm `latest=0.5.0`；registry tarball 与源码/文档一致；全新 DSH profile 无需手工改 manifest 或 tool policy 即可完成默认加载。

## 9. 配置兼容性

| 场景 | 0.4.0 | 0.5.0 计划 |
|------|-------|------------|
| library `Config({})` / `ConfigSchema({})` | disabled/reject | 保持 disabled/reject |
| DSH plugin entry `Config({})` | disabled/reject（受 patch 影响） | disabled/reject（patch 显式写入 ready defaults） |
| DSH bundle patch | disabled/reject | enabled/agy-owned |
| 普通 npm install | 容易被误认为会进入 DSH | 明确只用于库导入 |
| DSH plugin add | 安装后还需手工 patch | 安装后默认 ready |
| 非空 DSH tools | 默认报 `UNSUPPORTED_TOOLS` | bundle 默认忽略 schemas，严格模式仍可 reject |
| 诊断入口 | 源码内 `npm run diagnose` | 发布 `dsh-agy-provider doctor` CLI |
| 安装 smoke | npm install + 手工 bundles | DSH 原生 plugin add |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| bundle 默认启用后 AGY 未安装 | 用户看到 Provider 但请求失败 | 启动只注册 adapter；doctor 给出 AGY 安装/登录/Agent 问题，不在启动时调用模型 |
| `agy-owned` 被误解为 DSH 工具桥 | 用户期待 DSH tool chunks | 文档、诊断、错误明确“忽略 schemas、AGY 独占、无双向 bridge” |
| doctor 为检查 profile 执行不安全命令 | 路径/命令注入风险 | 固定 argv、shell=false、白名单 profile 名、超时/输出上限、路径脱敏 |
| doctor 自动修改 YAML 覆盖用户配置 | profile 损坏 | 0.5 默认只读；无法保证结构化合并时不实现 `--fix` |
| DSH CLI/profile 格式在 RC 阶段变化 | 安装检查失效 | 固定 `0.1.0-rc.7`，使用实际 plugin add/dump-config 契约测试，升级单独审计 |
| CI process-tree 测试偶发失败 | 发布可信度下降 | 明确 ready/PID 握手、受控重复、失败时修复竞态而非长期 rerun |
| Trusted Publisher 未完成 | tag workflow 失败 | 发布前先核验 npm settings；未连接时使用 release candidate 或用户授权的本机 2FA 发布 |
| 默认变化影响严格用户 | 非预期忽略 DSH schemas | 只改变 bundle patch；`Config({})` 保持 reject，并提供显式覆盖/迁移说明 |

## 11. Definition of Done

0.5.0 只有在以下条件全部满足时才视为完成：

- V5-M1–V5-M5 的源码、测试、CLI、profile smoke 和安全边界完成。
- DSH 原生 plugin add 后 bundle 自动进入 profile，默认 enabled/agy-owned，无需手工 manifest 或 tool policy 修复。
- 程序化 Config 默认值和 one-shot/sessionMode 行为保持兼容。
- doctor 可从 npm 安装产物直接运行，机器输出稳定且 `quotaUsed=false`。
- Web/headless 自包含 smoke 与完整跨平台矩阵一次通过。
- Windows Node 24 process-tree fixture 不再依赖 CI rerun。
- tarball 不包含规划文件、凭据、本机路径、真实 Prompt/Response 或用户 profile 内容。
- 可选真实 AGY 复验不超过 2/12k/1k；未授权时不影响源码 release candidate 判定。
- 发布后 npm `latest=0.5.0`，全新 registry 安装闭环通过。
