## 1. 0.5.0 发布后审计

0.5.0 已完成 DSH 原生 profile 安装、bundle ready defaults、doctor CLI、跨平台 Mock smoke 和 Trusted Publishing。0.6.0 的主要缺口不再是“能否安装”，而是额度是否可预测、辅助调用能否降本、AGY Agent 能否按安全档位使用文件工具，以及图片输入能否通过当前 DSH/AGY 契约可靠落地。

| 维度 | 当前事实 | 0.6.0 缺口 |
|------|----------|------------|
| 自动重试 | Adapter 未覆写 `providerRetryPolicy()` | DSH retry 插件可把一次请求放大为最多 3 次 AGY 调用 |
| 辅助调用 | 忽略 `GenerateOptions.purpose` | compaction/session-title 与普通会话使用相同 model/effort |
| usage | 已向 DSH 发出 usage chunk | 安全日志没有 numeric token usage，难以解释额度消耗 |
| Agent 工具 | 当前 `deepseek-proxy` 实际为 `tools: []` | 没有可安装的 read-only/workspace-write 档位 |
| 写入边界 | Provider 未设置 AGY cwd/workspace | 不能安全开放 `write`，也无法证明写入被限制在目标工作区 |
| 图片 | DSH 有 `ImageBlock` 和 `AttachmentStore` | Adapter 只支持 text/reasoning；AGY CLI 没有原生 image 参数 |
| doctor | 可检查 package/profile/AGY | effective config 解析不完整，dump-config 失败可能被静默降级 |
| 模型目录 | `agy models` 可发现 14 个模型 | 目录不提供 image modality，不能只凭模型名称宣称识图 |

## 2. 版本目标

0.6.0 聚焦五个用户结果：

1. 一次 DSH 请求默认只发起一次 AGY 模型调用；任何额外 retry 都必须显式启用并有硬上限。
2. compaction 和 session-title 可显式路由到更便宜的模型/effort，未配置时保持 0.5.0 行为。
3. 保留 tool-free Agent，并提供可审计的 read-only 与 workspace-write Agent 模板；写入能力默认关闭且限定到显式工作区。
4. 对 raster image 建立真实协议闸门：只有 DSH attachment → AGY `view_file` → 模型识图闭环实测通过，才声明 image modality。
5. doctor 能从 effective profile 解释 retry、purpose、Agent、workspace 和 image 状态，并给出不消耗额度的修复建议。

目标链路：

```text
DSH Web/headless
  → dsh-agy-provider
     ├─ quota-safe retry / purpose routing
     ├─ tool-free | read-only | workspace-write Agent policy
     └─ optional ImageBlock staging bridge
  → local AGY CLI
  → AGY account quota and models
```

## 3. 关键产品决策

### 3.1 默认不自动重试

- Adapter 显式实现 Provider retry policy，默认 `maxRetries=0`。
- 可配置 retry 的硬上限为 2；只有用户显式 opt-in 才允许 DSH 外层重试。
- 默认候选 retry codes 仅限 `RATE_LIMIT`、`SERVER`、`TRANSPORT`；`TIMEOUT`、`EMPTY_RESPONSE`、`QUOTA`、`PERMISSION_REQUIRED`、`UNSUPPORTED_CONTENT` 和任何写工具失败不自动重试。
- `sessionMode=resume` 的 conversation mismatch fallback 与 DSH 外层 retry 分别计数并记录；不得形成无界或隐式乘法。

### 3.2 purpose 路由默认继承

- 新增 `purposeRoutes.compaction` 与 `purposeRoutes.sessionTitle`，每个路由可覆盖 model、reasoning effort 和 Agent。
- 未配置的字段继承普通请求，保持 0.5.0 兼容；不偷偷将所有用户切到硬编码模型。
- doctor 验证目标模型存在于有效目录、effort 合法、Agent 可发现；请求日志只记录 purpose 与最终 route，不记录 Prompt。

### 3.3 Agent 能力采用三个独立档位

| 档位 | 工具 | 默认状态 | 用途 |
|------|------|----------|------|
| tool-free | `[]` | 默认；保持 `deepseek-proxy` | 纯文本、最低副作用与较小上下文 |
| read-only | `find_by_name`、`grep_search`、`view_file`、`list_dir` | 显式安装/选择 | 查找、读取、识图实验 |
| workspace-write | read-only + `multi_replace_file_content`、`replace_file_content`、`write_to_file` | 显式 opt-in | 仅在指定工作区编辑文件 |

- 不修改用户现有 `deepseek-proxy`；包内模板使用独立名称，避免覆盖。
- workspace-write 不包含 `run_command`、网络、浏览器、MCP、subagent、图片生成或任务调度。
- 所有模板保持 `commandExecutionPolicy: off`；绝不传入 `--dangerously-skip-permissions`。
- workspace-write 必须配置 canonical `workspaceRoot`，Provider 将其作为 AGY cwd；拒绝 home、盘根、空值、越界和无法解析路径。
- AGY 仍是工具执行者；工具事件只做安全计数，不转换为 DSH tool calls，不记录参数、路径或文件内容。

### 3.4 Agent 安装必须显式、可预览

- npm postinstall 不修改 `~/.gemini`。
- CLI 增加模板 inventory 与安装预览；默认显示目标、diff 和冲突，不写文件。
- 只有显式 apply 才写入，已存在同名 Agent 时默认拒绝；允许用户主动选择备份后替换。
- doctor 检查 Agent frontmatter、工具白名单、execution policy 与 effective profile 的一致性。

### 3.5 图片采用受控临时文件桥

- DSH 侧只接受正式 `ImageBlock`；Provider 通过 `AttachmentStore.readImage()` 读取经过完整性校验的 raster bytes。
- 每个请求创建私有临时目录，以安全扩展名写入随机文件名，通过 `--add-dir` 暴露给具备 `view_file` 的 Agent，并在 `finally` 删除。
- 不接收任意用户路径、远程 URL 或 Prompt 内 base64，不使用原始显示名，不把临时路径写入日志。
- 只有 AGY 实测确认 `view_file` 将图片交给模型、DSH Web 可以渲染/持久化图片且残余文件为 0，才对对应配置声明 `inputModalities: ['text', 'image']`。
- 若协议闸门失败，0.6.0 保持 text-only，发布稳定错误与证据；不得仅修改 metadata 假装支持识图。

## 4. 成功标准

1. 默认配置下，一次 DSH request 最多创建 1 个 AGY 模型进程；失败不会被 DSH retry 插件自动放大。
2. 显式 retry 配置经过 schema、hard cap、code allowlist 和测试，usage/attempt 数可解释且不含敏感内容。
3. `purpose=compaction|session-title` 能按配置选择 model/effort，普通会话路由不受影响。
4. package tarball 包含三个 Agent 模板；CLI 可预览/安装到隔离 AGY config，且不会覆盖既有 Agent。
5. read-only 能完成 list/find/grep/view，workspace-write 只能修改受控临时工作区；无 shell/network/MCP 能力。
6. 图片 fake transport 覆盖读取、staging、argv、取消、超时、清理和错误分类。
7. 只有真实 AGY 图片协议测试通过时，image modality 与 DSH Web attachment smoke 才进入 release；否则按 text-only negative result 收口。
8. doctor JSON 保持 `quotaUsed=false`，并稳定报告 retry、purpose、agent preset、workspace、image bridge 和 effective-config 错误。
9. Windows/Ubuntu/macOS × Node.js 20/22/24 verify/benchmark 通过；Ubuntu/macOS Node 24 profile smoke 通过。
10. 公共 CI 不读取用户 AGY/DSH 配置、不调用真实模型、不执行真实写入、不保存 Prompt/response/attachment。

## 5. 范围

### 必做

- quota-safe Provider retry policy 与 numeric usage/attempt telemetry。
- purpose-aware model/effort routing。
- tool-free/read-only/workspace-write Agent 模板、显式安装预览和 doctor 校验。
- 显式 workspaceRoot、cwd 与最小工具白名单。
- 图片 bridge 的 fake runner、协议实验、稳定错误与清理机制。
- effective-profile doctor v2、DSH Web/headless smoke、迁移和发布文档。

### 条件性交付

- 对外 image modality：必须通过真实 AGY `view_file` 识图和 DSH Web attachment 闭环。
- workspace-write 真实请求：必须只对自动创建的临时工作区执行，且用户已授权本计划额度。
- 0.6.0 tag/npm publish：必须在源码、CI、迁移和 registry version 检查全部通过后执行。

### 明确不做

- 不实现通用文件、PDF、音频或视频输入。
- 不实现 DSH ↔ AGY 双向 tool-call bridge，不把 AGY 工具事件转换成 DSH tool chunks。
- 不启用 `run_command`、shell、网络、浏览器、MCP、subagent 或自动权限批准。
- 不传入 `--dangerously-skip-permissions`，不自动修改用户全局 permission grants。
- 不重新开放 persistent transport，不改变 `sessionMode=full` 默认值。
- 不公开映射 `--json-schema`；当前 DSH `GenerateOptions` 没有 structured-output 字段。
- 不支持 temperature/maxTokens/stop、reasoning-delta 或 image output。
- 不通过 postinstall 修改 DSH profile、AGY Agent 或用户工作区。

## 6. 真实 AGY 额度预算

规划阶段真实模型请求为 0。实施阶段只有 V6-M3/M4/M5 的受控验证可以使用额度，硬上限为：

- 最多 8 次模型请求。
- 累计最多 50,000 input tokens。
- 累计最多 4,000 output tokens。
- read-only 最多 2 次、workspace-write 最多 2 次、图片协议最多 2 次、DSH Web 最终复验最多 2 次。
- 写测试只使用自动创建的临时目录和固定无敏感内容 fixture；完成后确认文件与 AGY 子进程残余均为 0。
- 图片测试只使用项目自建的简单 PNG fixture，不使用用户图片。
- 任一请求数/token 上限达到即停止；公共 CI、doctor、模型发现和 Agent 安装测试始终为 0 请求。

报告只记录请求序号、purpose、provider/model/effort、Agent 档位、工具事件计数、usage、耗时、退出状态、临时资源清理结果；不保存 Prompt、response 正文、工具参数、文件内容、路径、conversation ID 或凭据。

## 8. 详细实施计划

### V6-M0：基线与范围冻结

1. 复核 npm/GitHub/CI/DSH/AGY/Node.js、工作树和生产依赖安全基线。
2. 审计 DSH retry policy、purpose、ImageBlock/AttachmentStore、usage 与 AGY Agent frontmatter。
3. 核实当前 `deepseek-proxy` 为 tool-free，收集 AGY 已证实 read/write 工具 id。
4. 冻结兼容性、非目标、真实额度、发布与 negative-result 策略。

验收：计划文档与本地规划文件一致；源码/package version/registry 不变；真实请求为 0。

### V6-M1：额度安全重试与 usage

1. 覆写 Adapter retry policy，默认零 retry，配置硬上限 2。
2. 建立 retryable code allowlist；验证 timeout、empty response、quota、permission、content 和写入错误不自动重试。
3. 对普通 full、显式 resume fallback 和 DSH 外层 retry 建立独立 attempt 计数测试。
4. 将最终 numeric usage、attempt、purpose、route 和工具事件计数写入 whitelist-only telemetry；不记录 Prompt/response/path。
5. 增加 fake runner：一次请求的 process 数、abort/timeout 后残余进程、重试延迟和 provider Retry-After。

验收：默认请求只执行一次；显式 retry 可预测、有界、可诊断。

### V6-M2：purpose-aware 路由

1. 增加 compaction/session-title 路由配置与 schema，覆盖 model/effort/agent。
2. 在 request serialization 前解析 effective route；不改写冻结的 DSH request。
3. 校验 purpose model/effort/agent，并保持普通请求和未配置 purpose 完全兼容。
4. 增加模型目录刷新、未知模型、Agent 缺失和 dynamic discovery fallback 测试。
5. 提供针对当前 Gemini 3.7 Flash 的推荐降本示例，但不设为所有用户的隐式硬编码默认。

验收：辅助请求可独立降本，普通会话 route 与 0.5.0 一致。

### V6-M3：Agent 能力档位与安全写入

1. 在 package 中加入 tool-free、read-only、workspace-write 模板与 schema/inventory 测试。
2. 扩展 CLI：列出模板、生成安装预览、显式 apply；冲突默认拒绝，不做 postinstall。
3. read-only 只启用 find/grep/view/list；workspace-write 只额外启用 replace/write，保持 command execution off。
4. 增加 workspaceRoot 校验、realpath/canonicalization、cwd、越界/盘根/home/symlink 拒绝与 Windows 路径测试。
5. 映射 `--disable-slash-commands`；workspace-write 仅在明确选择后映射 AGY accept-edits 模式，绝不跳过权限。
6. fake runner 验证 argv 不含 shell、敏感路径日志或未授权工具；真实额度测试只在临时工作区完成 read/write 最小闭环。

验收：默认 Agent 无变化；read-only 无副作用；write 只能影响显式临时工作区。

### V6-M4：图片协议闸门

1. 将 attachments 作为图片模式所需依赖注入；text-only 路径不因服务缺失而失败。
2. 扩展 serializer 识别 ImageBlock，拒绝 tool-call/tool-result 和未知块并返回稳定 code。
3. 通过 AttachmentStore 读取 bytes，按请求 staging，使用随机文件名、受控 MIME/扩展名、权限和总量限制。
4. 将 staging dir 通过 `--add-dir` 交给 read-only Agent，引导 `view_file` 读取；finally 在成功、失败、abort、timeout 时清理。
5. fake runner 覆盖多图顺序、损坏引用、附件服务缺失、Agent 无 view_file、工具权限和清理失败。
6. 使用简单 PNG 完成最多 2 次真实 AGY 协议验证；本轮盲测返回正向像素答案，但没有已安装 `view_file` Agent 事件来源和 DSH Web 闭环证据，不增加 model modality。
7. 按条件性交付收口：记录 staging/清理/错误事实，保持 text-only metadata 与稳定错误，不扩大额度。

验收：成功路径必须是真实模型根据像素作答；仅读取文件名、Prompt 描述或占位文本不算通过。

### V6-M5：doctor v2 与集成门禁

1. doctor 从 effective dump-config 读取 agent、sessionMode、retry、purpose、workspace、image 和 model capability。
2. dump-config timeout/non-zero/parse failure 产生稳定 issue code，不再静默降级。
3. 检查 selected Agent frontmatter 与工具白名单，检测 write Agent 无 workspace、image Agent 无 view_file、purpose model/Agent 缺失。
4. 修复建议保持只读，输出精确 profile patch/Agent install 命令；不实现全局自动修复。
5. Web/headless Mock smoke 覆盖默认 tool-free、read-only argv、write 临时 workspace 和条件性 image attachment。
6. 完成跨平台矩阵、pack inventory、日志/路径/fixture 泄漏审计和进程/临时目录清理。
7. 在额度剩余时执行最多 2 次真实 DSH Web 最终复验。

验收：doctor 与公共 smoke `quotaUsed=false`；所有矩阵一次通过；真实验证严格受预算控制。

### V6-M6：迁移与发布

1. 更新 README、安装、Agent 能力矩阵、兼容性、迁移、CHANGELOG 和发布清单。
2. 明确 0.5.0 用户无需迁移；新 Agent、purpose、retry 和 image 均为显式配置，默认仍为 tool-free/full/text。
3. 运行 typecheck、tests、benchmark、pack、doctor、Web/headless smoke、registry version 占用检查和敏感内容审计。
4. 将 package version 更新为 0.6.0，提交后等待完整 CI。
5. 创建精确 `v0.6.0` tag，通过已配置 Trusted Publisher 发布。
6. 从 registry 全新安装到隔离 profile，复验 default、doctor、Agent templates 和 Mock/条件性 image 能力。

验收：npm `latest=0.6.0`；registry tarball 与源码/文档一致；不复用旧 tag，不保存 npm token。已完成：`v0.6.0` 指向 `948049c`，CI `32224840640`、Trusted Publishing `32225108295` 和 registry 隔离 smoke 均通过。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| retry 重复收费或重复副作用 | 额度/文件不可预测 | 默认 0 retry；写入和 timeout 类失败不可自动重试 |
| purpose route 指向不可用模型 | 辅助调用失败 | doctor/catalog 校验；未配置时继承普通 route |
| write Agent 越界 | 用户文件受损 | 显式 workspaceRoot、canonical boundary、最小工具白名单、临时目录真实测试 |
| headless permission 无法审批 | 请求挂起或误授权 | 保持 permission fail-fast；不跳过权限；只在明确 accept-edits 档位测试 |
| `view_file` 不传递图片像素 | 假识图 | 使用像素答案 fixture 验证；失败即 negative result，不声明 modality |
| 临时图片泄漏 | 隐私/磁盘风险 | per-request dir、随机名、finally 清理、残余扫描、日志不含路径 |
| dynamic models 无 modality | UI 能力误报 | 只有协议和 model capability 都验证后才声明 image |
| AGY/DSH RC 契约变化 | 配置或事件失效 | 固定版本、doctor version gate、fixture 与真实最小复验 |
| Agent installer 覆盖用户配置 | 自定义丢失 | preview 默认、冲突拒绝、显式 apply/backup、无 postinstall |
| 范围过大 | 版本拖延 | 图片按条件性交付；通用文件、音视频、shell 和 tool bridge 明确延期 |

## 11. Definition of Done

0.6.0 只有在以下条件全部满足时才视为完成：

- V6-M1–M3 的额度安全、purpose 路由和 Agent 档位全部完成。
- 默认配置行为保持 tool-free、sessionMode full、text-only、单次 AGY attempt。
- workspace-write 只能修改受控临时工作区，不具备 shell/network/MCP，权限不会被全局跳过。
- doctor v2 与所有公共 CI/smoke 保持 `quotaUsed=false`。
- 图片只有在真实协议闸门通过时发布；否则文档和 metadata 明确 text-only，并以稳定错误收口。
- 真实额度不超过 8/50k/4k，报告不含敏感正文、路径、工具参数或凭据。
- 跨平台 CI、tarball inventory、安全审计和资源清理通过。
- 发布后 npm `latest=0.6.0`，隔离 registry profile 复验通过。
