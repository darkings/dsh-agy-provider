# dsh-agy-provider 0.8.0 开发计划

状态：规划完成，尚未开始实施。本文只定义 0.8.0 的范围、门禁、预算和发布条件；当前 package version、npm `latest` 和 `v0.7.0` tag 均保持不变。

## 1. 版本主题

0.8.0 的主线是：

> 在保留 0.7.0 DSH-owned 权限与工具所有权的前提下，将 AGY 1.1.15 的 persistent `stream-json` 输入协议产品化，并建立 DSH rc.7/rc.8 双版本兼容门禁。

图片输入作为条件性交付：只有像素盲测、DSH Web、工具所有权和临时资源清理全部通过，才公开 image modality；否则继续保持 `imageInput: experimental`/text-only，不阻塞 persistent transport 主线。

## 2. 规划基线

| 项目 | 0.8.0 规划基线 |
|------|----------------|
| Provider | `dsh-agy-provider@0.7.0` 已公开发布，npm `latest=0.7.0` |
| 发布证据 | `v0.7.0` → `b94fa32`；Trusted Publishing 与 registry permission matrix 已通过 |
| AGY | 本机 `1.1.15`；正式支持 `--input-format stream-json`，可在单一 conversation 中逐行执行多轮 |
| DSH stable | `@deepseek-ai/dsh@0.1.0-rc.7` |
| DSH next | `@deepseek-ai/dsh@0.1.0-rc.8`；作为前向兼容目标，不直接替换 stable 基线 |
| 工具所有权 | 0.7.0 默认 `dsh-owned`；DSH Session cwd、permission preset、ToolRuntime 和 approval 是唯一权威 |
| 正式 transport | one-shot；每个模型请求启动一个 AGY print-mode 子进程 |
| persistent prototype | 已有 fake worker 生命周期实现与测试，但尚未适配 AGY 真实 NDJSON frame |
| 图片 | 有安全 staging bridge；尚未公开 modality，且与 `dsh-owned` 下禁止 AGY internal tool event 存在冲突 |

## 3. 核心决策

### 3.1 one-shot 保持默认

0.8.0 即使通过 persistent gate，也先将 persistent 作为稳定 opt-in：

```yaml
transport: one-shot   # 默认，保持 0.7.0 行为
# transport: persistent
```

不在同一个版本中同时引入新 transport 并切换默认值。后续版本只有在 registry 用户反馈、崩溃恢复和额度数据继续稳定后，才评估默认迁移。

### 3.2 一个可信 DSH Session 对应一个 persistent worker

```text
DSH Session A → AGY worker A → 同一 AGY conversation
DSH Session B → AGY worker B → 同一 AGY conversation
sessionless / auxiliary request → one-shot
```

- 同一 worker 同时最多一个 active turn；同一 Session 串行。
- 不把一个 AGY conversation 共享给多个 DSH Session。
- worker 不跨 DSH 进程重启持久化；本版不新增磁盘 conversation 映射。
- compaction、session-title 和没有可信 `sessionId` 的请求默认走 one-shot，避免上下文串线。

### 3.3 不在已写入请求后自动 fallback

一旦请求 frame 已成功写入 AGY stdin，就不得自动重发 one-shot，因为无法证明上一次调用没有计费或产生输出。只有 spawn/ready/写入前失败，才允许按明确策略回退。

### 3.4 DSH 继续拥有工具和权限

persistent transport 只改变模型请求承载方式，不改变 0.7.0 的安全边界：

- AGY 负责推理和受约束的 tool-call 生成。
- DSH ToolRuntime 执行 read/write/edit/search、shell、web、MCP、skill、subagent 等当前实际暴露的工具。
- Provider 不维护工具名白名单、不执行 DSH 工具、不传 `--dangerously-skip-permissions`。
- 每轮仍最多返回一个 tool call；并行 tool call 不进入 0.8.0。

## 4. 目标与成功标准

1. `transport: persistent` 使用 AGY 1.1.15 的真实 NDJSON 输入协议，不再依赖自定义 fixture envelope。
2. persistent worker 在正常、abort、timeout、CLI crash、malformed frame、output limit 和 dispose 后都能确定性回收；下一轮不会接收残余事件。
3. DSH-owned tool loop 在 persistent 模式下完成 tool-call → DSH execution → tool-result → 下一轮模型回答，权限矩阵不回退。
4. DSH rc.7 保持全量回归；rc.8 的 Web/headless、Provider contract、AttachmentStore 和 ToolRuntime matrix 通过后才扩大兼容声明。
5. 真实对照证明 warm-turn 首事件延迟中位数至少改善 15%，累计 input tokens 不比等价 one-shot 高 5% 以上，且无重复/丢失响应。
6. doctor v4 能只读报告 configured/effective transport、AGY version gate、worker capability、DSH compatibility 和安全 fallback 边界。
7. 公共 CI、doctor、模型发现、fake worker 和 registry smoke 始终 `quotaUsed=false`。
8. 只有满足图片条件性门禁时才声明 `inputModalities: ['text', 'image']`；否则 metadata 保持 text-only。

## 5. 范围

### 必做

- AGY 真实 persistent frame 协议适配。
- Session-affine worker pool、并发上限、idle TTL、ready/turn/shutdown timeout。
- one-shot/persistent 共用事件解析、错误分类、usage 和 tool protocol。
- DSH rc.7/rc.8 双基线兼容测试。
- persistent 模式的 DSH-owned tool-result 多轮回流。
- doctor v4、allowlisted transport telemetry、安全日志和资源清理。
- 双语 README、安装、迁移、兼容矩阵、CHANGELOG 和 release checklist。
- pack artifact、Web/headless、跨平台 CI、Trusted Publishing 与 registry 隔离复验。

### 条件性交付

- 公开 image modality。
- 图片与非空 DSH tools 同时存在时的受控 bridge。
- Gemini 3.7 Flash High 与 Gemini 3.1 Pro High 的固定盲测能力声明。

### 明确不做

- 不直接调用 Gemini API，不管理 OAuth/refresh token。
- 不把 persistent transport 设为 0.8.0 默认值。
- 不持久化 AGY conversation ID、Prompt、response 或 worker payload 到插件磁盘。
- 不实现并行/批量 tool calls。
- 不映射 AGY CLI 未提供的 `temperature`、`stop`、`maxTokens`。
- 不公开未经验证的 `reasoning-delta`。
- 不支持 image output、音频、视频或任意用户文件路径输入。
- 不允许 AGY 和 DSH 同时执行通用文件、shell、网络或 MCP 工具。
- 不自动合并 PR、不复用旧 tag、不在公共 CI 中调用真实模型。

## 6. 配置草案

最终字段名以 V8-M1 契约审计为准；初始设计如下：

```yaml
transport: one-shot                 # one-shot | persistent
persistentIdleTtlMs: 30000          # 0 表示 turn 后立即关闭
persistentReadyTimeoutMs: 10000
persistentFallback: before-accept   # never | before-accept
```

复用现有配置：

- `maxConcurrent`：同时存在的 active AGY process/worker 上限。
- `maxQueue`、`queueTimeoutMs`：worker slot 与同 Session 串行等待上限。
- `timeoutMs`：单 turn 上限。
- `maxOutputBytes`、`maxEventLineLength`：输出和 frame 上限。
- `sessionMode`：one-shot 兼容路径继续支持；persistent 不与 `resume` 叠加两套 conversation 恢复语义。

兼容规则：

| 配置 | 0.7.0 | 0.8.0 计划 |
|------|-------|-------------|
| 未配置 transport | one-shot | one-shot，行为不变 |
| `transport: persistent` | 无此字段 | AGY ≥1.1.15 且可信 Session 时启用 |
| sessionless request | one-shot | one-shot |
| auxiliary purpose | one-shot | 默认 one-shot |
| `sessionMode: resume` | opt-in | 仅 one-shot；与 persistent 同时配置时 doctor 报冲突 |
| `toolPolicy: dsh-owned` | 默认 | 保持默认与同一安全边界 |
| `imageInput: experimental` | opt-in | 保持兼容；是否升级由 V8-M5 gate 决定 |

## 7. 真实 AGY 额度预算

公共 CI 与默认开发命令为 0 请求。真实请求必须由独立脚本显式确认，并按阶段记账：

| 阶段 | 最大请求数 | 最大 input tokens | 最大 output tokens | 用途 |
|------|-----------:|-----------------:|------------------:|------|
| V8-M1 协议捕获 | 4 | 30,000 | 2,000 | 确认 frame、终态、conversation 与多轮 stdin |
| V8-M4 对照门禁 | 12 | 90,000 | 6,000 | 6 个 one-shot 与 6 个 persistent 等价样本 |
| V8-M5 图片门禁 | 6 | 45,000 | 4,000 | 两个模型、固定盲测图片与 Web 闭环 |
| **总硬上限** | **22** | **165,000** | **12,000** | 任一上限命中立即停止 |

规则：

- 串行执行真实实验，先验证协议，再做性能，再决定是否进入图片 gate。
- 只记录 request 序号、模式、模型、effort、耗时、首事件延迟、usage、事件计数、退出状态和 cleanup；不记录 Prompt、response 正文、路径、tool arguments、conversation ID 或凭据。
- 最后一个请求可能在返回 usage 后越过 token 上限；脚本收到 usage 后立即停止，不再发下一次。
- abort/crash/fallback 场景不得为“补齐样本”自动重发真实请求。

## 9. 详细实施顺序

### V8-M0：规划与范围冻结

1. 核对 0.7.0 tag、npm latest、CI、AGY、DSH stable/next 和工作树。
2. 复盘 one-shot、experimental transport、image bridge、tool protocol 与 doctor v3。
3. 冻结配置兼容、非目标、额度、安全和发布边界。
4. 创建本计划并同步中英文 README 入口。

验收：仅文档/规划变更；package version、tag、registry 和运行代码不变。

### V8-M1：协议与兼容性门

1. 捕获 AGY 1.1.15 `--input-format stream-json --output-format stream-json` 的真实 input frame、事件序列和终态。
2. 验证同一进程连续 turn、conversation identity、Unicode、空响应、错误 frame 和 stdin close 行为。
3. 对比现有 prototype 与真实协议，移除只适用于 fixture 的 ready/requestId/shutdown 假设。
4. 在隔离依赖树中审计 DSH rc.7 与 rc.8 的 `LlmAdapter`、`GenerateOptions`、`StreamChunk`、AttachmentStore、Session 和 ToolRuntime 变化。
5. 建立 stable/next 双 lane；next 失败只阻止 rc.8 声明，不破坏 rc.7 用户。

Go 条件：真实 AGY 可在单进程完成至少 3 个连续 turn，并为每轮提供唯一终态和可归属 usage；否则 persistent 主线 no-go。

### V8-M2：persistent adapter

1. 将 experimental worker 状态机改为 AGY 真实 NDJSON adapter，并与现有 `AgyStreamParser` 共用事件语义。
2. 以可信 DSH `sessionId` 建立 worker affinity；同 Session 串行、跨 Session 受 `maxConcurrent` 限制。
3. 增加启动、ready、turn、idle、shutdown、crash、reset 状态和大小/时间边界。
4. worker 关闭时清理父子进程树；Windows 使用 tree termination，POSIX 使用 process group。
5. 保持 one-shot 代码路径独立可回退，不让 persistent 重构破坏 0.7.0。

验收：100 轮 fake serial、8 Session 并发、worker cap、idle TTL、abort、timeout、crash、malformed frame、output limit、dispose 全部通过且残余进程为 0。

### V8-M3：DSH-owned tool loop 与安全 fallback

1. 在 persistent 模式下执行 message 和单 tool-call 两类 final envelope。
2. DSH 执行 tool 后，将 tool-result 作为同一 worker 的下一轮输入；验证 read/write/shell/local web/MCP round-trip。
3. 保留 tool schema/arguments/result 上限、未知工具拒绝、原型污染防护和唯一终态规则。
4. 请求写入 stdin 后禁止自动 one-shot 重发；只允许 ready/写入前 fallback。
5. 任一 worker correlation、conversation 或内部 AGY tool 异常都 fail closed 并 reset worker。

验收：0.7.0 的 15/15 permission matrix 在 persistent adapter fake/local fixture 下等价通过；Provider 不执行工具、不放宽 permission。

### V8-M4：真实可靠性与收益门禁

1. 先用最小 prompt 验证 cold start 与 warm turn，再执行 6+6 等价样本。
2. 比较 first-event latency、total duration、input/output tokens、process starts 和失败率。
3. 至少覆盖两个 DSH Session 的交替调用，确认无输出、usage 或 conversation 串线。
4. 记录并执行 go/no-go：warm-turn 首事件 P50 改善 ≥15%，input token 增幅 ≤5%，所有样本唯一终态且 cleanup 通过。
5. 若收益门失败，`transport: persistent` 不进入 public config；保留 one-shot 并记录 negative result。

### V8-M5：条件性图片门禁

1. 生成不在文件名/Prompt 中泄露答案的简单 PNG fixture，验证答案来自像素而非文字提示。
2. 证明 AGY internal tool event 可限定为只读 `view_file`，目标只能位于 per-request staging directory；无法验证 name/path 时立即 no-go。
3. 验证图片与 DSH Web 默认非空 tools、`dsh-owned` tool loop 和 persistent/one-shot 路径的共存边界。
4. 对 Gemini 3.7 Flash High、Gemini 3.1 Pro High 各执行固定样本；只有 6/6 像素答案正确且无越权事件才声明对应能力。
5. success、模型失败、abort、timeout、worker crash 后临时目录和文件残余必须为 0，文件权限保持 `0600`。

Go 条件：像素证据、事件限制、Web 闭环、工具所有权、清理五项全部通过。任一失败则保留 experimental/off 和 text-only metadata。

### V8-M6：doctor v4 与 RC 门禁

1. doctor 报告 transport configured/effective、AGY persistent capability、worker limits、fallback、DSH stable/next 和 image gate 状态。
2. telemetry 仅记录 transport、attempt/turn/process counts、worker reset reason、latency/usage 数值和 bridge outcome。
3. 完成敏感字段、日志、argv、stdin frame、临时文件、进程树和 package inventory 审计。
4. CI 覆盖 Node 20/22/24 Provider verify、Windows/macOS/Ubuntu DSH native stable matrix、rc.8 compatibility lane 和 self-contained smoke。
5. 从源码 pack artifact 安装到 disposable Web/headless profile，复验 one-shot 默认与 persistent opt-in。

### V8-M7：迁移与发布

1. 新增 0.8.0 migration 与 release checklist，更新中英文 README、installation、Provider contract、compatibility、CHANGELOG。
2. 只有 M1–M4、M6 全部通过后才 bump `package.json`/lockfile 到 0.8.0；M5 按 go/no-go 写入真实能力声明。
3. 运行 `npm ci`、verify、benchmark、pack、doctor、Web/headless、permission matrix 与 PR CI。
4. CI 全绿后创建精确 `v0.8.0` tag，通过 Trusted Publishing 发布。
5. 从 npm registry 全新安装 0.8.0，复验 latest、默认 one-shot、persistent opt-in、doctor v4、Mock、cleanup 和条件性 image metadata。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| AGY input frame 与 prototype 不同 | transport 无法直接复用 | M1 先捕获真实协议；不把 fixture envelope 当生产契约 |
| persistent 响应串线 | 跨 Session 数据泄漏 | 一 Session 一 worker、单 active turn、唯一终态、异常立即 reset |
| 自动 fallback 重复计费 | 额度和副作用不可预测 | frame 写入后绝不重发；fallback 只允许 before-accept |
| worker 泄漏 | 长期占用进程/内存 | idle TTL、dispose、process-tree cleanup、残余扫描 |
| DSH rc.8 breaking changes | 插件装载或工具失败 | stable/next 分离；rc.7 不退化，rc.8 未通过不扩大声明 |
| 图片必须依赖 AGY 内部 `view_file` | 与 DSH-owned 所有权冲突 | 只允许 staging-only 受证实例外；无法验证则不公开 modality |
| benchmark 样本过少 | 错误切换默认值 | 0.8 只提供 opt-in；后续版本再评估默认迁移 |
| persistent 长上下文扩大 token | 成本上升 | usage gate、目的路由保持 one-shot、input 增幅上限 5% |
| 日志泄露 frame/path | Prompt 或文件信息暴露 | allowlisted numeric telemetry；不记录 payload、路径、正文和 conversation ID |

## 11. Definition of Done

0.8.0 只有在以下条件全部满足时才算完成：

- DSH rc.7 无回归，rc.8 compatibility 结论有可复现证据。
- persistent 使用 AGY 真实协议，并以 stable opt-in 方式接入；one-shot 保持默认。
- worker lifecycle、并发、abort、timeout、crash、cleanup 和 before-accept fallback 全部通过。
- DSH-owned permission/tool matrix 在新 transport 下不退化，Provider 不执行工具或跳过权限。
- 真实 persistent gate 在 22/165k/12k 总预算内完成，或者按 no-go 停止且不发布虚假能力。
- 图片仅在 V8-M5 全部通过时公开；失败时 text-only 声明和稳定错误保持准确。
- doctor v4、跨平台 CI、packed artifact、Web/headless、敏感内容审计和 registry smoke 全部通过。
- package version、tag、Trusted Publishing、npm latest 与 GitHub release commit 精确对应。

## 12. 实施顺序

```text
V8-M0 planning
  ↓
V8-M1 AGY protocol + DSH rc.7/rc.8 gate
  ↓ go
V8-M2 persistent adapter
  ↓
V8-M3 DSH-owned tool/lifecycle safety
  ↓
V8-M4 real reliability & cost gate
  ├─ no-go → stop/re-scope, no 0.8 publish
  └─ go
       ├─ V8-M5 conditional image gate
       └─ V8-M6 doctor/RC/security
                ↓
             V8-M7 release
```

第一实施步是 V8-M1，不先修改默认配置，也不先重写现有 one-shot adapter。
