# dsh-agy-provider 0.9.0 开发计划

状态：已实现并合并至 `main@14ed413`（`v0.9.0`），`0.8.0` 已合并至 `main@b7c9a45`（`v0.8.0`）。本文定义 0.9.0 的目标、范围、门禁、设计与发布条件（V9-M0~M4 已完成，见 `task_plan.md` / `progress.md`）。

## 1. 版本主题

0.9.0 的主线是：

> 让 AGY 模型在 DSH 中像原生模型一样无感可用 —— 用户在 DSH 设置面板即可完成配置，项目目录与工具权限由 DSH 自动接管，无需手动 ``workspaceRoot``。

一句话验收：

* 新用户在 DSH Web 设置面板点选 Provider=AGY，即可在模型列表看到 AGY 模型并直接对话
* 已有项目无需额外在插件里配置项目目录，工具调用自动使用 DSH 当前项目的 workspace
* 从 DSH 视角，AGY 模型的 `listModels/resolveModel/stream/tool-call/image` 行为与官方 `deepseek` Provider 一致（在明确不支持的维度上给出可操作错误，而非静默丢弃）

## 3. 核心决策

### 3.1 工作区无感化 — DSH 已有项目目录即插即用

```text
用户在 DSH Web 打开文件夹 / 新建 Session
        ↓ header.cwd (canonical)
  workspaceRegistry.resolveByPath(cwd) → workspace.path
        ↓ sandboxPolicy.resolve(session) → {mode, workspaceRoot}
  resolveDshContext 校验：cwd == workspace.path == policy.workspaceRoot
        ↓
  Provider 直接使用 DSH 的 canonicalCwd，不读 Config.workspaceRoot
```

* `dsh-owned` 下 **废弃 `workspaceRoot`**：`src/provider/config.ts` 保留字段作兼容但标记 `deprecated`，`src/provider/agy.ts:resolveAgyAgentRuntime` 在 `dsh-owned` 时强制 `workspaceRoot=undefined`，不再校验
* legacy `agy-owned` 仍支持显式 `workspaceRoot`，但设置面板默认隐藏该字段，仅当用户显式切到 `agy-owned` 时才展示并提示“建议改用 dsh-owned”
* 文本模式无需 workspace：`resolveDshContext` 仅在 `toolSchemaCount>0` 时才要求 workspace 可信，纯文本对话始终可用
* 错误可操作：若用户未打开文件夹就发工具请求，返回 `DSH_WORKSPACE_MISMATCH` 并附 `doctor` 建议“请先在 DSH 中打开项目文件夹”，而非泛泛的 `UNSUPPORTED_TOOLS`

### 3.2 设置面板 — 由 Config Schema 驱动，而非第二套配置

DSH Web 的设置面板由 `Cordis/Schemastery` 的 `Config` schema 自动生成（title/description/enum/number 约束），并通过 `ctx.llm.registerConfigurableProviders` 声明可配置路由：

```ts
ctx.llm.registerConfigurableProviders([{
  provider: 'agy',
  settingsNamespace: 'dsh-agy-provider',
  settingsPath: 'dsh-agy-provider', // profile dsh-agy-provider config 所在路径
}])
// + registerModelDiscovery('dsh-agy-provider', discover)
```

* 本插件的 `Config` schema 已由 `schemastery` 定义，0.9.0 只需补齐 UI 元数据：`title/description/role/advanced.collapse`，为 `provider/model/agent/toolPolicy/transport/imageInput` 增加 `description` 与 `enumNames`
* `workspaceRoot` 在 schema 上加 `deprecated: true` 并在面板中隐藏（`dsh-owned` 时）
* 模型列表由 `agy models` 的 `registerModelDiscovery` 提供，设置面板的模型下拉直接复用，无需手写 `models:[]`

### 3.3 模型可见性 — 设置中可勾选要显示的模型

* 新增 `Config.visibleModels?: string[]`（空 = 显示全部发现模型；非空 = 仅显示勾选的 base 模型 id）
* `src/provider/agy.ts:listModels()` 在 `effectiveModels()` 之后按 `visibleModels` 过滤
* DSH 设置面板通过 `registerModelDiscovery` 拿到发现列表后，渲染为多选勾选框（类似其他 Provider 的模型开关），勾选结果写回 `visibleModels`；未勾选的模型不出现在 DSH 选择器，但仍可被显式 `model` 请求（兼容历史配置）
* `doctor v5` 报告 `visibleModels: count + filteredCount` 与 `hiddenModels` 提示

### 3.4 模型与推理强度分离 — 统一由 DSH 选择

当前：`gemini-3.7-flash-high` / `medium` / `low` 为三个独立 `model id`
目标：`model: gemini-3.7-flash` + `reasoningEffort: low|medium|high` 由 DSH 统一选择

* `src/agy/models.ts` 新增 `normalizeModelId(id)`：去除末尾 `-(low|medium|high)` 后缀，`extractEffort(id)` 提取强度
* `src/provider/config.ts:configuredModels()` 与 `mergeModelCatalog()` 按 base id 去重，保留首个 `name/description`，不再保留三个变体
* `src/agy/models.ts:parseAgyModels()` 对 `agy models` 输出的每个 id 做归一化后再去重
* `src/provider/agy.ts` 兼容层：若请求 `model` 仍带后缀，自动拆为 `base + effort`（effort 优先取请求显式 `reasoningEffort`，否则取后缀），并记录 `DEPRECATED_MODEL_EFFORT_SUFFIX` warning
* `listModels()` 返回的每个 base 模型均带 `reasoning: {efforts: [low,medium,high]}`，DSH 面板的模型行即显示推理强度下拉，而非三个重复模型
* 面板中模型列表仅显示 base 模型，勾选即勾选该模型的全部强度档位

### 3.5 模型平权 — 与原生模型对齐的最小集

* **已平权**：`listModels/resolveModel/reasoningEffort/stream/usage/session`，`dsh-owned` 工具桥，`persistent` 性能
* **0.9.0 补齐**：
  * 转发 `temperature/maxTokens/stop`：DSH 的 `LlmCallConfig` 已有这些字段，`AgyAdapter` 需评估 AGY CLI 是否透传；若 AGY 暂不支持，则在 `resolveCallConfig` 阶段给出带迁移建议的 `UNSUPPORTED_*`，而非在 `stream` 中静默丢弃，并在面板上禁用对应控件并标注“AGY 暂不支持”
  * 模型发现与面板联动：`registerModelDiscovery` 使面板“刷新模型”按钮可触发 `agy models`，结果写入 `modelDiscovery` 缓存
  * `inputModalities`：保持 `text-only` 直至 V8-M5 图片四门全过；面板中 `imageInput` 仅暴露 `off/experimental`，并标注 experimental 限制
* **明确不做**：直接调 Gemini API、自动管理 AGY 登录、并行 tool_calls、持久化 `conversation_id` 到磁盘

### 3.6 设置面板中/英切换 — 跟随 DSH 当前语言

* DSH Web 的语言由 `navigator.language / DSH locale` 决定，插件不自行存语言状态
* `@deepseek-ai/schemastery` 的 `Schema.i18n(messages)` 已支持按 locale 合并 `$description/$desc`，DSH 设置面板按当前 locale 读取对应描述
* `src/provider/config.ts` 的每个字段通过 `.i18n({
  'zh-CN': { $description: '中文描述' },
  'en': { $description: 'English description' }
})` 提供双语，顶层 `Config` 亦 i18n 标题
* 无硬编码中文：英文为 fallback，CI 中校验每个有 `description` 的 schema 均有 `zh-CN` 与 `en`
* 校验方式：`tests/config.test.mjs` 增加 `config schema i18n 覆盖率` 单测，`doctor v5` 报告当前检测到的 locale 描述是否缺失

## 4. 目标与成功标准

1. DSH 设置面板可完成 AGY 的一键启用/模型选择/面板参数调整，无需手写 YAML
2. 任意已打开文件夹的 DSH Session，发工具请求无需配置 `workspaceRoot` 即可通过 `resolveDshContext`，`read-only/workspace-write/danger-full-access` 均由 DSH 接管
3. 纯文本请求在无 workspace 时仍可用；有工具请求在无 workspace 时返回可操作的 `DSH_WORKSPACE_MISMATCH` 与 `doctor` 建议
4. `workspaceRoot` 在 `dsh-owned` 下被忽略且面板隐藏，legacy `agy-owned` 仍兼容但标记废弃
5. 设置面板可勾选要显示的模型（`visibleModels`），未勾选模型不在选择器出现
6. `gemini-3.7-flash` 等模型不再拆为三个 id，推理强度由 DSH 的 `reasoningEffort` 统一选择（兼容旧后缀）
5. `temperature/maxTokens/stop` 的面板行为与原生 Provider 一致（支持则透传，不支持则禁用并提示）
6. `listModels/resolveModel` 在面板与 API 中与原生模型一致展示（id/name/contextWindow/reasoning）
7. `doctor v5` 报告 `settingsPanel/workspaceSource/effectiveWorkspace/visibleModels` 与废弃警告，CI 与 registry smoke 通过
8. 设置面板字段、模型勾选、推理强度下拉均按 DSH 语言实时中/英切换
9. 完整的 7 层测试流程（见 §10）全部通过

## 5. 范围

### 必做

* `Config` schema 补充面板元数据（title/description/enumNames）与 `workspaceRoot deprecated`
* `src/index.ts` 增加 `registerConfigurableProviders + registerModelDiscovery`
* `src/provider/agy.ts` 废弃 `workspaceRoot` 在 `dsh-owned` 的读取与校验，改为 DSH Context 权威
* `src/dsh/context.ts` 错误提示优化与 `diagnoseDshContext` 面板友好文案
* `src/doctor.ts` v5：新增 `settingsPanel` 与 `workspaceSource` 报告
* 文档：`docs/v0.9.0-migration.md`、`docs/dsh-provider-contract.md` 增补面板与 workspace 章节、中英文 README 同步

### 条件性

* `temperature/maxTokens/stop` 透传：以 AGY 实际 CLI 支持为准，面板控件按能力开关
* 图片 `inputModalities` 仍按 V8-M5 四门决定，0.9.0 不强行公开

### 明确不做

* 不引入第二套持久化配置存储；面板即 profile YAML 的可视化
* 不自动创建/猜测项目目录；始终以 DSH Session 的 `cwd` 为准
* 不在面板中暴露 `AGY_TOKEN` 或凭据输入

## 6. 配置草案

```yaml
# DSH Web 设置面板（可视化编辑 profile 的 dsh-agy-provider 配置）
enabled: true
provider: agy                 # 固定
model: gemini-3.7-flash       # 下拉：归一化后的 base 模型（推理强度分离）
visibleModels:                # 多选：设置中勾选要显示的模型，空=全部
  - gemini-3.7-flash
  - gemini-3.1-pro
agent: deepseek-proxy         # 下拉：deepseek-proxy / read-only 预设
toolPolicy: dsh-owned         # 单选：dsh-owned(推荐)/reject/agy-owned(legacy)
transport: one-shot           # 单选：one-shot/persistent
# workspaceRoot: 现已废弃 — dsh-owned 时面板隐藏，自动使用 DSH 项目目录
imageInput: off               # 单选：off/experimental
# 高级折叠
modelDiscovery: auto
# reasoningEffort 在 DSH 会话级选择：low|medium|high，对应 AGY --effort
```

兼容规则：

| 旧配置 | 0.9.0 行为 |
|--------|------------|
| 含 `workspaceRoot` 且 `dsh-owned` | 忽略，doctor `DEPRECATED_WORKSPACE_ROOT` warning，日志不含路径 |
| 含 `workspaceRoot` 且 `agy-owned` | 仍校验，但面板提示迁移到 dsh-owned |
| 不含 workspace | 直接可用，工具走 DSH Session cwd |
| 旧 `gemini-*-high` 后缀 | 自动拆为 base + effort，warning 提示改用面板推理强度选择 |
| 文本-only 请求 | 无需 workspace，直接 `stream` |

## 8. 详细测试流程（0.9.0 新增）

0.9.0 的测试分 7 层，全部 `quotaUsed=false` 除非显式标注真实额度。任何一层失败即阻断发布。

| 层 | 名称 | 命令/脚本 | 覆盖点 | 额度 | 产出 |
|----|------|-----------|--------|------|------|
| L1 | 单元（无 DSH） | `npm test` (`node --test tests/*.test.mjs`) | parser/serialize/limiter/models/tool-protocol/config(i18n)/dsh-context/diagnostics/doctor + 新增 `normalizeModelId/visibleModels/i18n` | 0 | 160+ cases, <5s |
| L2 | Adapter 集成（fake 进程） | `tests/agy-provider.test.mjs` + `tests/persistent-transport.test.mjs` 扩展 | listModels 过滤(visibleModels)、归一化(base+effort)、旧后缀兼容、workspace 无感(有/无 cwd)、transport 分发、tool 桥、abort/timeout/crash | 0 | fake fixture，覆盖 100串行/8并发 |
| L3 | DSH 自包含 Mock smoke | `npm run smoke:dsh:self-contained` | disposable Web/headless profile、`plugin add`、bundle 默认值、Mock 文本流、设置面板注册 `registerConfigurableProviders` 可见 | 0 | 隔离 `DSH_INSTALL_DIR` |
| L4 | 权限矩阵 smoke | `npm run smoke:dsh:permission-matrix` | read-only/workspace-write/danger-full-access × 文件/搜索/shell/web/MCP × 有/无 workspace 的 fail-closed | 0 | 15+ 场景 |
| L5 | 0.9.0 新增：设置面板 + 模型/强度 + i18n smoke | `npm run smoke:dsh:settings-panel` (新增) | 面板可启用/模型勾选(visibleModels) 生效→选择器可见性、base+effort 下拉、workspace 无感文本/工具、 zh-CN/en 切换时描述变更 | 0 | 需 DSH Web 定制 fixture |
| L6 | 跨平台 CI | `.github/workflows/ci.yml` | verify × Node20/22/24 × Win/Ubuntu/macOS + dsh-smoke × Node22/24 + capability-matrix | 0 | GitHub Actions 全绿 |
| L7 | 真实 AGY 抽样（quota） | `scripts/agy-protocol-experiment.mjs` 等按预算 | 3真实轮 warm 改善、base+effort 实际 `--effort` 透传、旧后缀兼容实测 | 预算内(见§7) | 仅本地显式触发，不入 CI |

**执行顺序**：L1 → L2 → L3/L4 并行 → L5 → L6 → L7（按需）。`npm run verify` 聚合 L1+L3 的 pack 校验；`docs/v0.9.0-release-checklist.md` 按此 7 层打勾。

**i18n 专项**：L1 中校验每个 Config 字段的 `i18n('zh-CN')` 与 `i18n('en')` 均存在；L5 中启动 DSH Web 时分别 `--locale zh-CN` / `en` 截图校验描述。

**模型专项**：L2 增加 `visibleModels=["gemini-3.7-flash"]` 时 `listModels()` 仅返回 1；`model: gemini-3.7-flash-high` 请求返回 warning 但仍成功。

## 9. 风险与应对

| 风险 | 应对 |
|------|------|
| DSH 设置面板 schema 元数据不生效 | 以 `schemastery` + 其他 provider 的 Config 为参照，先本地 Web 验证再发版 |
| AGY 不支持 temperature 等参数 | 面板禁用控件并明确提示，不伪装支持 |
| 用户仍手写 workspaceRoot 造成困惑 | 保留读取但忽略，doctor 给迁移建议，面板隐藏 |

## 10. 发布门禁

* `npm run verify` + `benchmark` + 7 层测试（L1~L6 全过，L7 预算内抽样）通过

* 纯文本无 workspace 可用，工具无 workspace 时错误可操作
* `doctor v5` 报告 `settingsPanel:ok + workspaceSource:dsh-session-cwd`
